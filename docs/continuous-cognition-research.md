# 持续清醒、可调算力与自主活动：研究评审

查阅：2026-11-08。用户希望在线且非睡眠时持续活动，放松时慢、专注时快，并保留时间连续性。本次仅研究与设计建议，未启动常驻自主服务，未更换正在训练的语言结构。原始论文网页、正文和散列保存在runs/continuous-cognition-research。

## 结论与必要区分

可以实现没有用户消息也会更新工作状态、继续已有目标、主动检查变化的系统。新的推理必须耗费计算；低频、小状态、事件触发和自适应深度可以减少平均成本，不能实现零成本无限思考。保持状态和记录时间，不等于这段时间一直推理；执行更多内部循环，也不自动获得现实时间感或主观体验。

区分四种量：实际经过秒数、内部更新次数、完成的推理／规划量、持久学习更新次数。推理可以改变短期活动而不改变长期权重；避免每次内部联想都写成亲历。离线和系统休眠间隔保留未知或无观察标记，不补造经历。

## 研究证据

| 来源 | 核心机制 | 能借鉴什么 | 限制 |
|---|---|---|---|
| Clockwork RNN (2014), https://arxiv.org/abs/1402.3511 | 模块按不同周期更新 | 快慢通道、降低全部模块同时计算的频率 | 论文测试音频与词分类；不是持续中文主体 |
| Skip RNN (2017), https://arxiv.org/abs/1708.06834 | 学习跳过状态更新，可加入计算预算 | 平静时少算、需要时更新 | 跳过期间没有产生新的神经推理；泛化与漏报需要测试 |
| ACT (2016), https://arxiv.org/abs/1603.08983；PonderNet (2021), https://arxiv.org/abs/2107.05407 | 按任务需求选择内部计算步数 | 专注时多推演、简单任务提前停止 | 是计算步数分配，不是提高芯片运行频率；ACT语言建模未获得大幅收益 |
| CfC (2021预印本／2022版本), https://arxiv.org/abs/2106.13898 | 显式时间间隔、连续时间动态的闭式近似 | 不等间隔更新、减少微分方程求解成本 | 其加速对照为微分方程网络，不能套到本项目或Transformer；不能跳过未知环境事件 |
| Continuous Thought Machines (2025), https://arxiv.org/abs/2505.05522 | 神经元处理自身激活历史，以同步关系形成表示，内部反复更新 | 有状态的内部推演、不同思考深度 | 阅读v1正文2.1、10、12.3：内部ticks与外部时间解耦；控制任务中可跨环境步保留动态；该版本尚未应用于语言建模 |
| Generative Agents (2023), https://arxiv.org/abs/2304.03442 | 观察、规划、反思驱动模拟活动 | 无用户消息也可继续活动的系统循环 | 使用自然语言外部经历记录和检索，不满足用户要求的纯内部经历路线 |
| Voyager (2023), https://arxiv.org/abs/2305.16291 | 自动课程、环境反馈、技能库 | 自主选择后续目标及验证行动结果 | 调用GPT-4、使用代码技能库，不是自身权重持续学习的证明 |
| Curiosity-driven Exploration (2017), https://arxiv.org/abs/1705.05363 | 以预测行动结果的误差提供探索奖励 | 有问题／有学习价值时决定做什么 | 预测误差不等于价值；需控制噪声追逐和无效循环 |
| DreamerV3, https://arxiv.org/abs/2301.04104 | 学习世界模型，通过想象轨迹改进行为 | 目标导向模拟、现实校验 | 想象是计算机制，不等于生理睡眠；醒着也可规划，睡眠巩固需另行定义 |
| Quiet-STaR (2024), https://arxiv.org/abs/2403.09629 | 在文本预测中学习隐含理由 | 有用推理的学习目标 | 不实现无输入自主运行，增加生成与训练成本；不能理解为添加思维链就解决连续活动 |

上述研究共同支持局部机制；没有一篇证明这个组合会形成主观意识，或在GTX1060上能以近零代价维持有价值的开放中文思考。

## 适合本项目的候选结构

建议使用持久工作状态＋小型时间感知循环核心＋预算调度＋按需语言／规划模块。循环核心维护当前目标、未决问题、最近证据、对下一事件的预测及可信度。具体目标可先采用显式可检查表示；这些属于运行状态，不能暗称全部为长期神经记忆。长期经历仍走已有来源和纠正约束。

工作循环：新观察／定时唤醒 → 按真实经过时长更新状态 → 估计需要关注什么 → 分配计算 → 内部推演或请求必要观察 → 核对收益／失败 → 更新工作状态 → 选择下一次唤醒。即使没有新消息，也可继续未完成任务；没有目标、没有变化时允许保持状态而不制造无意义输出。

三种工作模式是工程策略，不能拟人为已存在的生理状态：

- 放松：小核心低频推进未决任务，必要时读取少量记忆；重语言路径多数时间不执行。若声称此时有推理，要记录真实执行的更新，不能只有计时器。
- 专注：提高更新频率、增加单次推演深度，围绕当前任务分配资源；仍可被用户新输入打断。
- 睡眠巩固：执行回放、压缩或有边界的想象学习。推测不直接覆盖事实；唤醒后核验原记忆。完整实现仍是待办。

平均计算粗略为 f×C小核心 + λ×C重推理 + C观察／保存；f为轻循环每秒次数，λ为重推理平均调用次数。降低f或λ有机会节能；实际耗电还受显卡常驻、唤醒、操作系统负载影响，必须实测。没有任意固定频率或“低于若干瓦”的已验证承诺。

更接近用户设想的实现不只是外置计时器反复调用无状态语言模型：必须让内部工作张量跨调用保留，并让后续行动确实依赖它。调度器作为运行基础设施仍不可避免，不应冒称它本身就是神经思考。

## 现有系统的缺口

P11已有真实时长记录、最近传感状态和有限2秒环境预测；docs/time-world-implementation.md明确说明没有持续自主循环和端到端语言连接。现有语言候选主要是因果Transformer加只读神经记忆注入；会话历史与持久经历也未完成语义对齐。完整睡眠想象未实现。因此本提议属于新机制，不能说现有时间模块已经具备。

## 建议的有限验证顺序

先用简单可观察环境比较：仅用户／事件触发；固定频率全计算；小核心加自适应预算。使用同一任务、相同记忆和真实时钟，加入延迟目标、不规则事件、突发输入与平静时段。

评估：没有新用户输入时能否完成先前目标、关键事件遗漏率、响应时延、无收益循环次数、每小时CPU／GPU时间与能耗、旧记忆保持、重启／休眠标记和想象误写。空闲期由系统自发动作产生的结果要由环境核实，不能由模型给自己打分算成功。

验证真实时间与循环次数解耦：相同经过时长但不同调度次数应有合理一致的时间判断；有意义计算与仅保持状态需分别报告。先做独立小实验，再接语言模块；中文尚不能稳定交流时，不让它无限自我生成并以自身输出训练自身。

训练控制器需要任务完成、预测校准、错过事件惩罚和计算成本等明确学习信号。单纯加循环而没有可学习目标，不会自动产生有用思考。

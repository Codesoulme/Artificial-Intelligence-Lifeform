# 混合训练目标预算调度器

`spora.mixed_target_budget.MixedTargetBudget` 是独立、确定性的内存调度工具，**尚未接入现有训练系统**。它不访问文件、不执行前向或反向传播、不更新模型，也不负责采样、数据审核、记忆保护或多臂原子保存。

## 数据与计划

每个来源是一份有顺序的非空列表，记录格式为 `{'id': str, 'tokens': list[int], 'mask': list[bool]}`；同一来源内标识必须唯一，词元为非负整数。`mask[i]` 表示是否监督 `tokens[i]`，首位置必须为 `False`，每条至少一个目标。与 `spora.paired_order.padded` 相同，调用方计算下一词损失时应使用 `tokens[:-1]` 作为输入，并按 `mask[1:]` 对 `tokens[1:]` 构造标签；非监督位置和填充位置设为忽略值。调度器返回完整词元列表，仅裁剪掩码：靠后目标可继续看到此前所有原始上下文，依赖调用方使用正确的**因果注意力**，不得使用双向注意力。

计划是逐更新的整数配额列表，每步必须包含全部来源名称，可给某来源 0，但单步总数必须大于 0。调度器按来源名排序，再按各源输入顺序消费目标；不会随机打乱或自动重复。构造时校验各来源全计划的可用目标足够。若一条记录横跨更新，下一次使用该来源时从上次停止的目标序号继续，并保留完整上下文；非连续监督位置也支持。`target_start` 是该条原始监督位置列表中的零起始序号，不是词元位置。`target_count` 是该片段保留的真实目标数。

```python
from spora.mixed_target_budget import MixedTargetBudget, normalized_loss

sources = {
    'story': [{'id': 's', 'tokens': [1, 2, 3, 4],
               'mask': [False, True, True, True]}],
    'dialogue': [{'id': 'd', 'tokens': [1, 9, 8, 7],
                  'mask': [False, False, True, True]}],
}
plan = [{'story': 2, 'dialogue': 1}, {'story': 1, 'dialogue': 1}]
schedule = MixedTargetBudget(sources, plan, microbatch_size=1)
update = schedule.prepare()
```

`update['quotas']` 为每源目标数，`update['denominator']` 是整个更新的总目标数。`update['microbatches']` 的每项包含 `rows`、`target_count` 和同一个全局 `denominator`；批次大小限制的是记录片段数，不是词元数。调用方逐微批对**有效目标损失求和**，检查实际标签数量等于 `target_count`，再执行 `normalized_loss(loss_sum, target_count=..., denominator=...)` 并累计梯度。最后才进行一次优化器更新。不能把每个微批均值相加；若手头是均值，需先乘上该微批有效目标数。模块只检查调用时提供的数字范围，无法自行确认损失是否真的按这些目标求和。分布式训练的梯度平均及缩放由调用方另行处理。

目标预算只控制被监督位置；不同来源的上下文长度、填充及实际计算量可能不同，等目标数不等于等计算。两个对照臂分别使用本模块时，相同配额不证明公共输入或目标相同；需要调用方比较最终张量、掩码、源次序与预算。模块也不保证所有用户自定义额外掩码、数据增强或截断操作与计划一致。

## 提交与恢复

`prepare()` 在 `commit()` 前重复调用返回相同内容的深拷贝；中途不支持提交部分微批。整个更新成功后调用 `commit()` 才移动游标。计划耗尽时 `prepare()` 抛出 `StopIteration`。未提交时不能导出或载入状态；调用方遇到失败应丢弃已计算的梯度以及任何已经更新的状态，并从上一次完整检查点恢复。

`state_dict()` 含版本、绑定来源内容/顺序及计划和微批大小的 SHA-256、下一更新序号、各来源记录与目标游标、累计监督数。`load_state_dict()` 要求以完全相同的来源和计划构造实例，再按完整已提交更新重放并核对所有游标与累计数；错误时不会改变现有状态。改变来源任何内容、顺序、计划或微批大小都不能恢复。状态不保存正文，但摘要不应当成访问控制或抗恶意篡改认证。

调度器状态必须由调用方和对应的**所有对照臂**的模型、优化器、学习率调度器、随机状态、采样状态及更新计数一起原子保存；只有各臂完整成功后才能提交和持久化。如果某一臂先更新后失败，所有臂须回滚至共同检查点。本模块既不能验证上述模型状态，也不能为调用方保证磁盘原子性或崩溃一致性。P118 中的原个体冻结、散列和记忆行为检查同样需另行实现。

当前实现将全部来源和计划复制入内存、计算内容摘要；恢复重放所有已提交更新。它适合有界研究与合成验证，尚无流式数据读取、并行调度、记录族/位置覆盖审计或大规模资源基准。实际使用前需在独立适配层核验输入身份、长文上下文、跨臂配对、目标数、训练器损失归一化及恢复一致性，不能将本模块单独视为完整的严格实验。


测试只使用合成词元和一个 CPU 标量梯度；覆盖跨更新接续、原上下文保持、目标精确配额、不同大小微批的全局均值梯度、提交边界、各更新点恢复及非法状态。没有启动训练或访问真实数据。

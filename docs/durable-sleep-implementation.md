# P9/P10：增量事务保存与新版睡眠巩固

2026-11-05。用户授权先验证增量保存及崩溃恢复，再接入新版睡眠；中文训练保持暂停。父代码版本 a8b0774，固定计划见 configs/p9-p10-plan.json。

## 个体的存储与事务边界

新增 TensorStore，以 SQLite WAL、synchronous=FULL 保存内部张量。tensors 表按结构路径保存形状、精度、字节与摘要；head 表记录同一版本的结构、经历游标、元信息及全体张量摘要。没有原始事件、符号答案或供推理检索的事实表。

正常提交只写变化的张量及清单。内存中使用张量对象及修改版本识别未变化部分，新对象则计算摘要；骨干与封存段不会因一次新经历而重复序列化。成本仍包括遍历名称及更新清单，不能称为总开销与状态规模完全无关。不能通过绕过张量版本跟踪的底层内存修改来更新状态。

单写者事务从 BEGIN IMMEDIATE 开始，比较调用者读取的父版本，写入变化、删除被替换的旧形状，再提交清单和游标。竞争写者持有旧版本时明确失败，不静默覆盖另一条经历。读者在事务快照中读取清单和张量，不能混入未提交部分。

备份使用 SQLite 的在线备份接口，不能仅复制正在写入的主文件并忽略日志。checkpoint 会将日志回写并截短；compact 另外执行 VACUUM，以回收文件中的空闲块。后者是有成本的维护，不在每次经历之后自动执行。WAL 与旧备份也要计入磁盘预算。

崩溃验收在提交前、进入事务后、首个张量后、全部张量后、清单后、提交前和提交后，通过父进程强制结束工作进程。普通观察与睡眠替换各验证七个位置。每次检查读者看到完整版本、恢复后状态精确、下一次写入相同，并核对备份和整理之后仍可读取。

这是进程崩溃验证，不是真实断电或故障硬盘试验。FULL 的效果还依赖操作系统与设备遵守同步请求，不能给出所有物理故障下零丢失的承诺。

## 睡眠究竟做了什么

本轮实现有限历史的离线行为蒸馏。教师是当前个体，学生是独立、随机初始化的低秩神经因子。每个已写满的 64 时刻段可以单独转存；尚在接收经历的段不能封存。骨干、地址、当前判断和其他段都不参与参数更新。

对某层历史矩阵 M，固定查询坐标 q，训练 L、R，使 LRq 近似 Mq。rank 16 学生每层包含 90×16 与 16×90 两个因子。训练查询遍历有限词表的 64 个键×64 个局部时刻，目标来自教师矩阵的神经读出；不存事件表，不使用其他模型权重。

因此这是对已知有限地址域的行为转移，不是对从未见过的事实或开放语义泛化。训练探针与转存后检查覆盖同一个有限域，独立性来自新经历流及不同底座；不能称封存查询从未进入过转存目标。教师错误也可能被保留，额外用真实环境标签核对历史、当前判断和未知拒答。

RLS 的逆相关证据仍然承担未知判断。本轮没有删掉它或漏算成本，而是利用对称性精确保存上三角，读取时恢复完整矩阵。每层从 8,100 个数降至 4,095 个数；它不是低秩学生自行学会的压缩。

每段两个记忆层的总量：

| 内容 | 转存前标量 | 转存后标量 |
|---|---:|---:|
| 历史读出 | 16,200 | 5,760 |
| 地址相关证据 | 16,200 | 8,190 |
| 总计 | 32,400 | 13,950 |

减量为 56.94%，其中部分来自学生的低秩表示，部分来自辅助矩阵的精确打包。当前任务只有 16 种结果，这使低秩表示较有利；不能外推为任意经历都能达到同样压缩率。

通过后，原历史矩阵在子状态中被两个因子替代，不随该个体保存；查询按时刻取相应封存段并计算神经读出。已有父快照继续单独保留用于回滚，其磁盘成本不应隐藏。一次睡眠不会使固定骨干变小，也没有实现无限容量。

## 验收、拒绝与继续学习

开发流 2210000 比较 rank 16/24/32，每种包含 SVD 控制与 600 步学生训练。根据开发结果选择 rank16，并在运行新流 2220000 之前保存选择文件。独立阶段使用三个既有随机基础模型，各两个环境，每条链连续三段、192 次经历。

每次拟议转存都检查所有有限键/时刻的教师行为，分别统计教师认为已知与未知的查询，要求各组至少 95%，同时要求当前通道输出完全一致。实际经历的有效历史、最早部分、不可信观察、错误组合拒答、当前值与未见当前值也逐项验收。数据不足的组单列不适用，不以平均数遮盖失败。

第二、三段开头增加对旧键的可信纠正；既检查新当前值，也保留早期历史，随后继续其他观察。每次接受后都从数据库重新加载，独立进程只加载便携检查点验证旧回忆，不读取事件记录。

公共 sleep 命令只有行为门槛和至少 20% 的段状态减量通过后才提交；失败只返回诊断，旧版本不变。单元测试专门强制拒绝候选，验证没有写入。

## 控制实验与结论边界

- 不转存、直接清理：用于确认历史确实需要某个神经载体。
- SVD：对同一个源矩阵作解析低秩近似，是强基线；如果它同样成功，就不能宣称睡眠训练更好。
- 等步数全矩阵重演：保留原矩阵、同样运行 600 个优化步，观察没有减少容量时的行为。它不是严格等 FLOP 的在线更新实验；报告给出乘加计数，后者仍属后续研究。
- 原密集表示：作为存储大小与读取耗时对照。

本轮只压缩历史区，当前矩阵保持活动状态，因此后续纠正通过不等于“已经解决共享快慢通路的所有冲突”。也未实现语义抽象、世界模型想象、自生成课程或对来源可信度的学习。

## 读取与文件大小的代价

旧格式保持可读；含封存段的便携文件采用 growing-v2，并由同一组编解码器支持 SQLite。原个体文件不被改写。

当前符号路径按需还原选中的段，产生临时计算及张量；字节接口目前会还原各段并建立读取计划。因此持久状态变小不等于推理内存和延迟同步降低。实测包括这一开销，不能用磁盘减量宣称回答更快。优化成直接低秩计算或有限的按需驻留是之后的工作。

三段封存、第四段待用的完整状态从 145,800 降至 90,450 个标量，减少 37.96%。由于固定骨干占主体，完整文件只减少约 4.5%。SQLite 释放的块默认可以复用但文件未必立刻变短；VACUUM 或新便携导出后的体积另列。

## 本地交付与使用

- checkpoints/individual-durable.sqlite：原三次经历个体的精确存储迁移，旧 .pt 保持。
- checkpoints/individual-sleep-candidate.sqlite：从上述真实谱系继续的独立副本，追加 69 次明确标注的程序生成观察，共 72 次；第一段完成睡眠后仍可学习。
- checkpoints/individual-sleep-candidate.pt：对应便携导出。它没有换成另一个随机底座，也没有把合成环境说成真实用户经历。

~~~powershell
.\.venv\Scripts\python.exe -m spora.durable_cli --individual checkpoints/individual-durable.sqlite info
.\.venv\Scripts\python.exe -m spora.durable_cli --individual checkpoints/individual-sleep-candidate.sqlite ask 12
.\.venv\Scripts\python.exe -m spora.durable_cli --individual checkpoints/individual-sleep-candidate.sqlite ask 12 --time 0
.\.venv\Scripts\python.exe -m spora.durable_cli --individual checkpoints/individual-sleep-candidate.sqlite ask 12 --time 2
~~~

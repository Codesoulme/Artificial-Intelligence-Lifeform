## 执行顺序

1. P5：改进历史区的写入保护及拒答。先比较 Delta 与递归最小二乘（RLS）写入，开发流选定方法后，再做三个种子的新流审计。若失败，记录并开新版本，不能反复在同一审计集挑参数。
2. P6：让同一个候选继续经历并扩展容量。采用显式的有限历史分段，追加神经矩阵；测试扩展前后旧回答、继续学习及独立进程恢复。分段是设计先验，参数成本必须随容量计入，绝不声称无限压缩。
3. P7：构建尚未训练的字节级因果语言接口、保存/恢复和训练管线。仅使用随机字节作机制检查，检验未来信息隔离、梯度路径和记忆保护。禁止运行中文训练或下载大规模中文语料。
4. 自审、完整回归、汇总失败与边界、准备下一阶段中文数据方案，最后向现有 GitHub 仓库推送一个研究分支并汇报。

## 就绪门槛

- 记忆：三个种子，独立环境；8/16/32/64 次事件分别要求当前值、有效历史、未观察组合拒答达到 95%；可用未来时刻的拒答同样达标。分别报告最早部分和不可信观察。
- 负例不得仅有固定键偏移；覆盖随机错键、同键错时、开始前/未来及低信任先到的情形。
- 连续成长：至少跨四个 64 事件区间，在单个持久状态中追加与恢复；扩展动作本身不改变已存在参数或旧查询结果。全长历史读出仍须独立验收；同时间重写和溢出须拒绝。
- 参数来源：普通推理只读模型状态，不读原始事件、身份提示或答案表。删除相关神经状态必须损坏相应回忆，恢复必须还原。辅助优化器状态与主参数分别计费。
- 训练前接口：因果性、梯度、只读查询、原子保存、旧模型兼容和资源有界检查通过；不存在中文能力已经形成的表述。
- 发布：保留旧文件哈希，提交源码、配置、汇总证据及文档；权重/私有上下文不随仓库上传。

95% 只是本项目进入下一阶段实验的工程门槛，不是可靠性、通用性或生命性的证明。若某项失败，继续局部迭代；不通过删指标来制造就绪。

执行中追加的更严格条件（新审计尚未运行）：P5b 的 64 个不同实体诊断、全部早期诊断与未观察组合也逐项要求 95%；P6 同时检查四实体及 64 实体流，以及仍无可信观察的当前键。该补充由 P5 开发失败触发，不根据任何 P5b 封存结果放宽门槛。

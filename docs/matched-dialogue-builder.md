# 多轮与末条用户消息配对数据

`scripts/build_matched_dialogue.py` 只构造数据，不训练。输入为 UTF-8 JSONL，每行含 `group` 和交替排列的 `messages`（`role` 为 `user` 或 `assistant`，文本放在 `content`）。这与 WildChat、OASST 和 KdConv 的已构造候选原始行兼容；仅有 `tokens`、`mask` 的窗口不能还原原始对话，不能作为输入。传入的文件必须由使用者明确选为训练侧，且符合相应来源和用途的要求。

```powershell
cd D:/SPORA
.venv/Scripts/python.exe -m scripts.build_matched_dialogue --input 路径/train.jsonl --tokenizer 路径/tokenizer.json --output 路径/全新目录 --max-tokens 512
```

每个有前文的助手回答生成一对：`context.jsonl` 保留尽可能多的完整历史轮次；`last-user.jsonl` 只包含对应末条用户消息和同一回答。两边均以 `<|bos|>` 开头，消息用 `<|user|>`、`<|assistant|>` 和 `<|eos|>` 编码；只有最后助手正文和结束符计入 `mask`。两边按相同顺序写入，`pair_id` 和监督词元完全一致；最长记录限制包含所有标记。仅能放下最后问答时跳过，末条问答本身过长也跳过，不截断目标。旧训练器以 `length+1` 判断记录长度，使用时须保证所选训练长度与本工具上限相容。

`lineage.jsonl` 保存每对来源行、组、原对话标识、目标和保留上下文的消息偏移、移除消息数、词元数及原行元数据。`manifest.json` 记录输入、词表、脚本和输出摘要、上限和跳过统计；构造过程中若输入发生变化则失败。候选有 `identity` 时使用它区分相似组中的对话；带 `source_turn_offset` 的窗口按组和绝对偏移去重。其他记录使用 `sha256` 或消息内容作为标识；缺少稳定原对话标识的不同窗口无法可靠去重。重复位置若目标问答不一致则报错。

输出目录必须不存在，所有文件以独占方式创建；失败可能留下不完整的新目录，缺少清单的结果不可使用。程序拒绝路径组成部分中明显标为 test、final 或 heldout 的输入与输出，但路径检查不能识别改名或未标记的受保护数据；不得将此类材料交给工具。它不访问其他分区，也不做跨分区隔离或近重复检查。

工具不判断脱离历史的回答是否合理，也不核验质量、权利或用途许可；输出不意味着材料获准训练。先按对话族划分数据，并另行确认对照标签适合仅凭最后一条用户消息回答。若需严格配对训练，还须确保两臂按同一 `pair_id` 顺序抽样并记录实际呈现量；已有随机抽样训练入口未因本工具自动获得这一能力。小样例只能验证构造可行性，不能证明泛化。

# P31：自愈、DNA蓝图与内部记忆架构复核

本复核针对用户新增的“内置医生 + DNA蓝图 + 自愈闭环”汇总。目标是判断哪些机制能进入 SPORA 的工程路线，哪些内容需要先补足来源或实验。资料核对日期为2026-11-08；公开链接和本地证据均保留在本文件，具体论文数值不能直接移植到SPORA。

## 证据分层

| 机制 | 核验结果 | 对SPORA的决定 |
|---|---|---|
| MEMIT | 已核实。论文是 *Mass-Editing Memory in a Transformer*，arXiv:2210.07229。它研究的是对已有Transformer进行批量事实编辑，不等于终身经历记忆或无限容量。 | 作为未来参数编辑对照，不接入当前随机初始化语言路径。先测局部性、顺序编辑、冲突和重启。 |
| Titans | 已核实。论文是 *Titans: Learning to Memorize at Test Time*，arXiv:2501.00663。它提供测试时学习记忆的研究方向，不证明跨进程事务持久化或个体身份连续。 | 作为在线记忆算法对照；与现有事务保存、来源和时间标签分开验收。 |
| DeepSeek Engram | 已核实。官方仓库为 `deepseek-ai/Engram`，论文题为 *Conditional Memory via Scalable Lookup*。它是确定性N-gram查找的静态条件记忆，与MoE互补，主要解决模式重建和容量分配。 | 可做小规模中文词法/固定短语查找对照；不把它当作个人经历记忆，先在冻结核心上做隔离实验。 |
| EvalRX | 已核实。论文 arXiv:2610.25767，仓库为 `evalvitals/evalrx`。核心是预先封存验证集、探索失败机制、提出修复、在未参与探索的验证集上决定是否晋级。 | 直接借鉴为SPORA的健康检查和修复晋级协议。优先级高。 |
| DeepSeek Harness / dsh-superagent | 已核实为运行时和研究原型，见 `reports/deepseek-super-agent-review.md`。它提供事件、任务、执行器、恢复和权限边界，不是神经网络结构。 | 作为清醒循环、事件账本、恢复和工具执行层的参考。 |
| BSHDER | 有公开GitHub仓库 `Devanik21/BSHDER-Architecture`，仓库自述包含DNA EMA和参数破坏恢复实验；当前没有足够独立论文或复现证据支撑“损坏80%仍恢复”的普遍结论。 | 只采用“受保护影子副本 + 受控损坏恢复测试”这一工程思想，不采用生物学命名或未经复核的数字。 |
| SleepGate、EVAF、MEMOIR/TopHash、EditScope、FDCU、CRISP、Autognostic、ReviveMoE | 当前核验没有找到足够的一手论文、正式仓库或可复现实验来确认汇总中的具体方法和数字。 | 暂不进入主架构；任何后续采用都要补论文、版本、代码和独立复现。 |

## 必须修正的设计认识

“DNA蓝图”不能承担所有记忆职责。它适合保存模型结构和稳定参数的恢复参照，解决参数损坏和回滚；它不自动记录某个用户、某个时间发生过的事实，也不能证明模型拥有内部人格。SPORA需要把四种状态分开保存：冻结基座、可回滚的学习适配器、带来源和时间的经历账本、当前清醒工作状态。任何参数巩固都必须从账本产生候选版本，经过评测后再发布。

MEMIT也不能直接替代这套经历系统。它假设模型已经有可编辑的知识表征，而当前SPORA的语言接口仍在从随机权重学习中文；直接编辑MLP会混淆语言学习、事实写入和身份保持。当前路线应先保留现有神经记忆读写，完成中文对话和来源时间语义，再在独立副本上比较MEMIT、低秩适配器和现有快记忆。

“内置医生”应先是受约束的诊断器，而不是可以直接修改自身的第二个自由模型。它接收固定格式的失败轨迹、指标、状态版本和候选假设，只能输出诊断记录与候选补丁；晋级器在封存集上验证无回归后才允许产生新版本。诊断器本身不拥有写核心权重的权限，也不负责把推测写入经历账本。

## 推荐的新分层

```text
事件账本：输入、时间、来源、推断、动作、结果、纠正、巩固记录
        ↓ 可回放、幂等、带版本
清醒工作台：当前目标、未完成任务、时间状态、低频预测、工具结果
        ↓ 受预算驱动
语言与记忆网络：中文生成、神经记忆读取、短期状态和可训练适配器
        ↓ 睡眠候选
巩固器：回放、冲突检查、来源检查、旧能力保持、候选版本
        ↓ EvalRX式封存验证
版本发布器：快照、适配器、DNA影子参照、回滚指针
        ↓ 受限接口
工具执行器：授权、资源预算、取消、幂等、副作用回执
```

这套分层把“模型本体”“经历证据”“诊断工具”和“执行环境”分开，同时允许它们在同一个个体版本中协同。它比把所有能力堆进一个Transformer更容易验证，也更符合SPORA已经有的SQLite事务、时间状态、神经记忆和恢复机制。

## 优先级调整

1. 暂停P30权重更新，先完成角色明确对话子集的人工抽查。当前P30机械子集只有11,714条、约73万监督词元，不能直接称为已审核对话。
2. 采用EvalRX式修复协议：固定失败分类、预先封存新开发题、候选修复独立运行、无回归才晋级。P27/P28/P29的原始输出继续作为诊断轨迹保存。
3. 实现事件账本与清醒工作台的统一事件格式：事件ID、父事件、单调时间、墙钟时间、来源、置信度、状态版本、幂等键、校验和、是否已巩固。
4. 实现DNA影子参照的最小版本：只读EMA或周期完整快照，和活动权重分开保存；注入人工损坏测试，比较直接回滚、DNA恢复和重新训练。通过前不接入自动自愈。
5. 完成中文对话训练后，单独做Engram式N-gram查找对照。查找表只存静态词法模式，不能写入个人经历；需比较词法损失、开放聊天、复制风险和内存成本。
6. 最后再研究参数编辑和模块化容错。MoE、路由器三模冗余和大规模专家会增加当前小显存实验的变量，不能在语言数据质量尚未解决时加入。

## 当前训练决定

P28短故事试验说明故事比例过高会让故事开发NLL快速下降，同时损伤旧中文和聊天；P29的20%故事、20%普通文本、59%教学、1%基础配方保持了旧NLL，但开放聊天仍大量重复。P30应改为“79%已验证回放与基础语言、20%人工审核的角色对话、1%核心价值课程”，普通散文暂设为0%，故事只保留为独立研究分支。这个决定来自数据质量审计，不是架构名称推导出来的结论。

## 本轮：减少读取工作

原符号入口已经根据明确时刻定位一个历史段。需要改进的是尚未训练的字节接口：它原先对每个输入位置读取所有段，再加权组合。

默认启用 exact 路径：从个体已有张量生成临时读取计划。数值完全相同的矩阵只做一次矩阵与向量运算，仍保留各段不同的位置权重，再合并这些权重。它不删除段，也不改变每段的含义；数学结果与原式等价，浮点运算顺序改变，因此验收使用数值容差，不宣称逐位相同。

bounded 是可选研究路径，先使用每段的对角线、非对角部分范数及位置向量估计贡献范围，最多挑选两个段。只有遗漏影响的保守上界满足条件时才跳过其余矩阵，否则完整读取。默认没有开启近似筛选，因为当前随机接口通常给多个段相近权重，强行筛选会丢失贡献，计算判断也可能比直接读取更慢。

设某段输出为 v=Mq，分数为 s=(qᵀMq+qᵀk)/√d。对角部分可以低成本计算，其余项的绝对值不超过 ||M−diag(M)||F·||q||²/√d，形成分数上下界。用候选分数下界与其他段的上界，得到遗漏 softmax 权重上界 δ。所选输出重新归一化后，与完整读出的距离不超过 2δ·max||M||F·||q||。接受门槛为每次读取 L2 误差 1e-4。

上述推导在实数运算下成立；实现加了浮点裕量，仍不是区间算术证明。局部误差限制也不等于最终输出类别必定不变，所以同时测试完整接口的输出偏差和第一候选一致性。含糊、误导性的选择信号必须保留为失败回退用例。

来源只有神经参数，没有事件文本、事实表或外部答案。计划会复制部分张量用于计算，增加运行内存；它可以丢弃重建，不随个体保存。新观察、扩容、张量替换或原位修改都会使旧计划失效。在 PyTorch inference_mode 内创建、没有版本计数的源张量退回实时读取，避免错误复用旧内容。训练仍使用原有可微读取路径，不通过推理优化切断梯度。

### 复杂度与尚未完成项

- 同一矩阵的重复计算消除后，重型读取数从段数 P 降为不同矩阵数 U。每个位置仍需计算全部位置权重。
- 可选路径的描述量比较仍随 P 增长，约为 O(Pd)，通过后重型读取约为 O(kd²)；不是与总容量完全无关。最坏情况下仍完整读取。
- 空段重复较多时获益更明显；所有区域均不同、段数较少或读取后立即更新时，构建与分派开销可能抵消收益。
- 当前接口没有学会语义寻址。强选择性的数值构造验证了机制，不能据此称它知道“哪些往事与问题相关”。
- 保存与加载仍使用完整检查点。本轮没有实现磁盘按需载入，也未修改持久存储格式。
- 8/16 段实验只检验分配后的计算与输出保持；实际经历连续性仍只验收到 256 次。不得报告 1,024 次回忆已经通过。

## 原设计的“做梦”不是遗漏

总体设计第 9 节已经规定离线巩固、教师快照、回放、清理前验收和失败回滚；第 11.3 节另行规定世界模型及想象轨迹。二者应分开：

| 机制 | 要解决的问题 | 实施情况 |
|---|---|---|
| 睡眠式巩固 | 把近期内容转入较稳定的内部区域，测量能否释放旧空间 | P3 在旧结构上做过有限符号转存及继续纠正实验；尚未接入新的历史分段 |
| 想象推演 | 组合已有知识、预测行动后果、练习策略 | 尚未实现可靠的世界模型，不具备开展完整想象训练的基础 |

P3 的十二条链在其小范围协议内通过，不代表对时间历史压缩成功；其高负荷成绩也有下降。P5b/P6 改变了地址、历史和拒答方式，旧巩固代码不能直接视为新架构已经具备的能力。

新增下列实施顺序，防止睡眠模块长期停留在纸面：

1. 在只读的当前候选旁建立实验分支；教师包含真实快照，保留父文件。初次固定骨干及读写坐标，只更新单独的长期模块。
2. 使用明确属于训练分区的经历及回放，监督“目前判断”和“过去收到的内容”两个不同目标。不用未来审计答案转存。
3. 在分支中屏蔽待释放区域，检查旧历史、当前纠正、未知拒答及不可信观察；同时检查再收到新经历后的可塑性。每项至少达到预设门槛。
4. 对照“保留原段”和“等计算在线更新”，把辅助状态、回放、训练耗时、文件体积一起计入。搬移矩阵而没有减少总资源，不能称压缩。
5. 仅在新流、三种子及恢复验证全部通过后清理对应区域；失败则保留原记忆。先在副本模拟清理，不直接擦除唯一载体。
6. 世界预测可靠之后，才另开想象轨迹实验。推演内容必须保留假设来源，不能充当已发生的个人经历。

巩固可以在语言之前用符号环境试验；不需要等待模型会聊天。它还没完成集成，是实施缺口，不能用“已经有架构”代替结果。

## 持久化：建议先用 SQLite 事务保存张量

这里的职责是把神经状态可靠保存、减少重复写盘，不是另建一个供回答查询的事实库。建议下一轮评估 SQLite 的 WAL 模式及完整同步策略，事务中只存：

- 本次变化的当前矩阵、活动历史段及其逆相关证据；
- 同一个提交版本内的经历游标、模型版本和完整性摘要；
- 只读旧段的版本引用，以及恢复所需的结构配置。

骨干和未变化的旧段不需要每次重写。参数与游标必须同事务提交，不能出现游标已前进但记忆仍旧的半次经历。查询仍把相应张量送入模型计算，不向数据库询问符号答案。日志轮转、事务检查点及快照保留策略也必须计入磁盘上限。

先比较 SQLite 内直接保存张量二进制块与现有完整文件，避免过早引入跨文件事务。若后来将封存段外置为不可变张量文件，则必须先完整落盘，再提交引用；恢复、孤立文件回收与备份都要按一致版本操作，不能认为一次文件重命名能保证多个文件的一致性。

| 方案 | 推荐用途 | 本项目取舍 |
|---|---|---|
| SQLite + WAL | 本机单写者、事务一致性、按变化部分更新 | 优先做下一轮原型与崩溃恢复测试；尚未替换现有格式 |
| safetensors | 固定骨干、封存段的张量快照与按需读取 | 格式本身不提供跨文件事务或断电恢复；可作为补充 |
| RocksDB | 更大规模的写入与键值存储 | 可保留为后备；当前几 MB 个体不值得先承担其维护复杂度 |

存储验收应包括：提交前、中、后强制结束进程；恢复到完整旧版或完整新版；重启后的下一次写入一致；旧快照可打开；读者不看到部分提交；文件体积与完整提交时延随段数增长的曲线。进程终止测试不等于真实断电试验，操作系统与硬件同步保证也要如实记录。

## 已核对的外部来源

本轮阅读原始摘要、官方说明或源代码。借鉴机制不等于复现论文，更不保证组合后有效。

- [Large Memory Layers with Product Keys](https://arxiv.org/abs/1907.05242)：研究大内部记忆中的高效寻址。可作为后续学习路由的参考；本轮采用误差上界筛选，并非其实现。
- [Titans](https://arxiv.org/abs/2501.00663)：测试时更新神经记忆的研究，不能代替磁盘事务设计。
- [Language Models Need Sleep](https://arxiv.org/abs/2606.03979)：摘要分别描述回放辅助的知识转移与自生成课程；没有证明小型随机幼体可以照搬，也不保证转存后文件一定变小。
- [SQLite 原子提交说明](https://sqlite.org/atomiccommit.html)及[官方 WAL 实现](https://github.com/sqlite/sqlite/blob/master/src/wal.c)：分别核对事务恢复原理、日志帧与提交同步。WAL/PRAGMA 网页多次超时，因此同步细节另核对官方源代码，而非假称页面已经读到。
- [safetensors 官方说明](https://github.com/huggingface/safetensors)：张量存储格式、按需读取与零拷贝能力；不承诺所有设备转换均零拷贝。
- [RocksDB WAL 官方说明](https://github.com/facebook/rocksdb/wiki/Write-Ahead-Log-%28WAL%29)：日志与恢复机制；进程崩溃一致性与断电持久性要区分。

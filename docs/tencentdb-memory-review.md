# TencentDB Agent Memory：对 SPORA 的参考价值

审阅日期：2026-11-05。对象为 [TencentCloud/TencentDB-Agent-Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory)，固定提交 `2002196f2d7c22ea267cfcaf67c5a6fa861df681`。本次为文档与关键源码静态审阅，未部署服务、调用其模型接口或复现性能成绩。以下“建议”均不代表已实现。

## 判断

值得借鉴记忆管理方法，不建议把整套产品直接接成 SPORA 的个人记忆主体。它解决的是成熟语言模型在会话之间如何保存、组织和调用外部信息；本项目要验证的是经历如何改变个体的神经状态，并在没有身份文档和答案库时仍可读出。

该产品可以使用本地SQLite和文件，不等于必须接腾讯云。关键差别在读写内容：它保存对话、文本事实、画像和技能文档，再把内容交给调用模型；SPORA的现有SQLite主要保存神经张量与运行状态。数据库文件是否放在本机、是否与权重打包，都不能单独证明记忆已经进入参数。

## 核查到的实现

1. **分层文本记忆**：L0保存对话，L1抽取事实/事件/规则等原子内容，L2组织场景，L3提炼画像或团队工作准则。抽取和聚合依赖语言模型调用，保存层不是神经网络训练。[核心说明](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2002196f2d7c22ea267cfcaf67c5a6fa861df681/MemoryCore/README.md#L159-L171)
2. **写前比较**：`batchDedup`先检索候选，再调用模型判定新增、更新、合并或跳过。没有检索条件或判定失败时，存在全部作为新记录保存的回退。因此“有冲突处理代码”不等于保证始终消除矛盾。[候选与判定](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2002196f2d7c22ea267cfcaf67c5a6fa861df681/MemoryCore/src/core/record/l1-dedup.ts#L56-L135)、[判定规则](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2002196f2d7c22ea267cfcaf67c5a6fa861df681/MemoryCore/src/core/prompts/l1-dedup.ts#L16-L69)
3. **多路召回与预算**：关键词全文检索与向量相似度可并行，再用RRF合并排名；有条目数及字符预算。默认可以只用BM25，向量服务是可选项。该路径是外部文本检索，不是神经记忆稀疏读取。[混合读取](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2002196f2d7c22ea267cfcaf67c5a6fa861df681/MemoryCore/src/core/hooks/auto-recall.ts#L657-L792)、[预算处理](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2002196f2d7c22ea267cfcaf67c5a6fa861df681/MemoryCore/src/core/hooks/auto-recall.ts#L854-L918)
4. **按需展开**：实际代理代码把L3全文与L2场景索引放入系统上下文，场景正文需要时再取；L0/L1通过工具查询。这比把所有文本一次塞入上下文更有节制，但仍然依赖外部内容。[注入实现](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2002196f2d7c22ea267cfcaf67c5a6fa861df681/MemoryProxy/src/injection/injectors/tdai-profile-memory-injector.ts#L11-L35)
5. **来源与版本**：记录含来源消息、时间、场景、版本等字段。更新/合并会从活动检索库删除被替换的旧记录；追加日志另有保留与后续清理逻辑，不能据此认为所有原始内容立即消失，也不能把它等同于我们永久保留经历顺序的历史通道。[写入实现](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2002196f2d7c22ea267cfcaf67c5a6fa861df681/MemoryCore/src/core/record/l1-writer.ts#L190-L304)
6. **技能归纳**：语言模型读取会话，通过工具创建或修改可复用技能资产，有资源、版本及后续分配。归纳得到文档，不是把新技能训练进主模型；没有runner时抽取返回空候选。[技能抽取](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2002196f2d7c22ea267cfcaf67c5a6fa861df681/MemoryCore/src/core/skill/skill-extractor.ts#L148-L356)
7. **Wiki、代码图与权限管理**：文档结构化、代码关系查询、资产绑定与访问控制都是实用工具层能力。不同调用者可绑定不同资产；这种管理不自动构成连续的个体身份。[知识服务](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2002196f2d7c22ea267cfcaf67c5a6fa861df681/MemoryKnowledge/README.md)、[整体结构](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/2002196f2d7c22ea267cfcaf67c5a6fa861df681/README.md#L240-L269)

## 应做进内部结构或学习机制的部分

这里的“内部”包含可训练神经部件与控制其更新的确定性规则，不要求把磁盘事务、计时器或权限检查都变成神经元。

| 参考机制 | SPORA里的转化方式 | 已有基础与缺口 | 优先度 |
| --- | --- | --- | --- |
| 写入前比较新旧信息 | 设置可训练的写入判定，分辨新增、纠正、补充、重复、未确定；依据来源、证据、时间与作用范围更新 | 已有当前/历史分离及外部可信标记；缺少学习得到的来源判断与语义冲突识别 | 高 |
| 来源及版本追溯 | 将亲历、别人告知、推测、模拟等来源类型编码进神经记忆；当前判断允许更新，历史保留当时收到的内容 | 已有低可信观察保留与时间序号；尚无一般化的多来源推理 | 高 |
| 先概括、后细节 | 用小型可学习路由先选择相关历史段，再做较重读取；不确定时扩大读取或明确未知 | P8已有计算合并及有界筛选，但没有学会语义寻址；需在真正写满的多段上测试 | 高 |
| 多层、不同更新速度 | 快速经历区、较稳定的概念/规律区，以及较慢形成的自身状态表征；具体层数由实验决定 | 已有历史封存压缩，尚未验证语义抽象和完整自我表征 | 中，衔接后续巩固 |
| 按变化触发后台整理 | 以新信息量、误差、冲突和资源预算触发巩固，候选先验收再替换；不必每次交互全量处理 | P9/P10已有事务和睡眠发布门槛，可复用，完整想象仍在待办 | 中 |
| 经验提炼为技能 | 给模型提供将成功经历归纳为可执行策略并通过反馈优化的训练路径 | 当前没有自主行动策略；先设计接口，实际能力留待后续课程 | 后期 |

分层并非照搬四个目录或写四份提示词。若慢层仍是每次注入的身份文本，或者神经路由选中后读取外部答案，这仍未达到参数内记忆目标。应通过断开外部内容、冷启动、对应张量消融和恢复验证来源。

重要性与真实性必须分开。频繁出现、对任务有用、情绪强烈都不等于正确；重复的同一传闻也不等于多份独立证据。项目提示词在合并后允许提升priority，这可作为检索排序启发，不能直接变成我们的置信度增长规则。

## 应通过后续训练学会的部分

这些是学习内容与策略，不宜现在硬编码成固定人设、固定分类清单或永远不变的行为脚本。

| 能力 | 需要什么训练条件 | 现在需预留的支持 |
| --- | --- | --- |
| 看懂“这句话是纠错还是另一个时间/对象的事实” | 语言理解、实体指代、时间与矛盾对照；可先用符号任务验证机制 | 来源、对象、时间及作用范围表征 |
| 从很多经历中总结规律 | 有反例的概括任务、独立泛化检验、与原经历核对 | 快慢更新通道及可回溯的证据关系 |
| 判断什么值得记、何时值得回忆 | 未来任务收益、记忆容量与读取成本的反馈，避免只奖励短期成绩 | 可训练写入/读取门与明确成本信号 |
| 理解不同人的偏好和关系 | 多人交互、归属判断、变化与纠正的样例 | 个体自身、交互对象及信息来源的区分 |
| 形成稳定但可修正的行为倾向 | 长期反馈、跨会话一致性和纠错实验 | 连续个体状态；不能因更换调用者就替换整个人格 |
| 归纳解题方法、选择工具并验证结果 | 任务、工具返回、成功失败反馈与迁移评估 | 工具接口、动作结果记录和技能更新路径 |

“以后学习”不表示放着运行就会自动出现。必须有输入、学习目标或反馈，以及能够写入自身状态的通道。直接把别人总结的技能说明塞入提示词，只能算读取说明书；训练后在没有那份说明书时仍可迁移执行，才支持技能已内化的判断。

## 保持在外部工具和工程层的部分

- **Wiki与代码图**：将来用于查资料、分析代码、获取新观察。精确版本的源码、文件路径、完整合同或文档更适合可核对的外部存储；不能要求有限参数无损记住无限资料。模型可学习理解和使用这些内容，同时保留工具边界。
- **BM25、向量数据库、RRF**：可用于外部资料搜索或研究对照。内部借鉴的是多线索寻址和有限读取，不能直接把文本检索包装为参数记忆。神经路由还应与全读、简单路由及近似检索比较，不能预设一定更好。
- **权限、审计、备份、版本管理、迁移**：由确定性软件保障；模型可以学习如何申请与使用权限，但不应依赖模型自己学会才阻止越权。本项目已有可靠张量保存路径，不必为了统一技术栈换成整套服务。
- **技能文件库和团队资产管理**：以后需要多人协作时可以作为工具或教学资料。共享一份资料不等于两个个体共享同一次亲历，更不等于合并人格。
- **代理和上下文注入**：适合给现成助手提供外部记忆，不适合作为SPORA“它始终是它”的实现依据。

其L3聊天画像主要描述用户，工作模式则提炼团队准则。这与模型自身的自传、身份连续性是两个问题。理解每个调用者不同的习惯，不要求把模型的自我状态换成那个人设。

## 对公开成绩的解读

README声称PersonaMem从48%提升到76%（增加28个百分点）。本次在所检出源码中检索了该基准名，仅找到中英文README中的结果表与一句说明，未找到与该数字配套的完整评测配置、数据划分、原始输出及复现入口；未独立复测。它可作为进一步考察的线索，不能直接推导SPORA会获得相同收益，更不是参数内学习的证明。

部分能力在路线图中仍属后续计划，例如面板里的L1–L3直接编辑；底层已有更新接口不代表面板功能都完成。评估应以实际使用路径和固定提交为准。

仓库声明MIT许可。如以后直接复用具体代码，应保留相应版权和许可，并核对第三方组成部分的条件。本次没有把第三方代码复制进SPORA运行模块。

## 建议顺序与可证伪条件

先研究**带来源的写入判定**，随后研究**小预算的神经路由**。这两项直接对应误改旧知识和经历增加后的读取成本，而且可以先用有限符号任务开展，无需提前恢复中文训练。完整睡眠想象和语言课程继续保留在[待办](TODO.md)，本次仅提出建议。

写入试验应同时回答：“目前相信什么”“某一时刻收到过什么”“这是亲历、转述还是假设”。加入重复传闻、多来源冲突、可信纠正、对象不同但内容相同等对照；不能只测写入成功率，而忽略旧经历是否被抹除。

读取试验使用具有不同实际内容的4/8/16段，与全读及当前P8路径比较准确率、遗漏率、拒答、回退率、延迟、额外参数和存储成本。路由错误时必须可以回退；不能只用大量空段证明成长后仍快。

持续身份试验则更换调用者和外部角色描述，保持同一份个体状态，检验自身经历不被改写；同时允许它记住不同人的偏好并正常调整表达。保持身份与适应交流应分别验收。

这些才是从该项目得到的、适合我们路线的研究增量；安装整套外部记忆服务本身不能替代这些实验。

# 相对评分与无正确候选的拒绝对照（2026-11-17）

## 方法

冻结原有两个路由头及 DeepSeek 底座。每个问题先取得不提供事实时的原始分类分数，再逐一加入四个候选（正确、同人不同属性、错人、否定）；计算“无候选分数减候选分数”，差值越大表示候选越使模型认为无需更多经历。选择差值最大的候选，只有差值严格超过门槛才接受；另构造仅有后三种错误候选的集合。

门槛取自 4 组校准题的 12 个错误候选的最大差值，严格大于才接受。这只是演示一种拒绝策略；校准数量极小，且这 4 组已用于难反例头的校准，不能当未接触数据。测试为之前已经观察的 8 组题，也不能作为独立验收。相对分数是分类头原始 logits 的差，不是经过校准的概率；每个候选被分别输入，不是模型真正检索出的多条记忆。

## 结果

| 指标（各 8 组） | 简单成对头 | 难反例头 |
|---|---:|---:|
| 四个候选中正确候选排序第一 | 8 | 7 |
| 有正确候选时正确接受 | 0 | 3 |
| 有正确候选时错误接受 | 0 | 0 |
| 有正确候选时全部拒绝 | 8 | 5 |
| 三个候选全错误时仍接受 | 0 | 2 |

简单头选出了正确候选，但校准门槛使其全部拒绝；难反例头在两个无正确候选的集合中错误接受。后者在四候选条件中同样存在的正确项掩盖了这些误接受，说明只测排序第一不能验证拒答可靠性。

这一研究对照不能估计真实错误率，也未验证候选检索、身份确认、事实真实性、多轮上下文、冲突、时间或持久记忆，更不适合接入正式运行。下一步需要更大、按来源及对话分组的独立校准与测试集，明确对无答案集合的错误接受率和有答案时的漏掉率；数据不足时不把排序分数当事实依据。

本机结果：`runs/deepseek-memory-need-relative-score-20261117/result.json`，约 104 秒；基础权重、候选与其结果前后摘要一致。两项测试覆盖正确选择和门槛相等时拒绝，未改写正式记忆。

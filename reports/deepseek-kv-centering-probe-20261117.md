# 固定键中心化的随机特征对照

在 [较长中文语料实验](deepseek-long-kv-feature-probe-20261117.md) 的相同两段文本、第 6 层两个 KV 头、三个长度和三个投影种子上，对每个历史窗口用其最早 128 个 key 的均值作为固定中心，将全部 key 减去该中心，再做同样的随机特征读写。中心由实验提供；当前研究状态没有绑定、保存或自动恢复这个中心，因此本次只验证数学对照，不是可直接用于在线状态的实现。

对同一 query，把所有 key 减去相同向量只会给各注意力分数加上相同常数，精确 softmax 理论上不变；实测精确输出前后最大绝对差不超过 7.40×10⁻⁶。中心化后的平均 key 范数在三个长度下分别约 11.46、12.84、13.21，原值约 16.94、16.79、16.59；query 平均范数约 20.74。这些数值跨两段与两个头取均值，不能代表全部层或语料。

| 历史长度 | 原随机特征 / 中心化 / 均值基线：平均均方误差 | 中心化低于原方案 | 中心化低于均值 |
| ---: | ---: | ---: | ---: |
| 128 | 0.1080 / 0.1031 / 0.0349 | 6/12 | 0/12 |
| 512 | 0.0728 / 0.0710 / 0.0247 | 5/12 | 0/12 |
| 1,024 | 0.0598 / 0.0738 / 0.0415 | 1/12 | 0/12 |

这些组合共享同一批 query，12 项不是独立样本。此固定中心在本设置下没有解决误差问题；不能据此断定其他中心、随机特征数或经过训练的表示必然无效。由于本轮修改了已有诊断入口并使用新结果路径，旧结果文件保持原样；不能把不同脚本版本当成同一个可复现环境。

查询在完整历史下生成，目标是单层注意力向量而非端到端回答；未验证自主写入、多主体纠正、真实状态保存或断电恢复。两段中文语料来自项目已有训练文件，可能包含文档拼接，也可能为底座见过的文本。底座和语料散列前后相同，正式个体未修改。运行约 93 秒，PyTorch GPU 峰值约 3.54 GiB；9 项既有状态与注意力检查通过，但它们没有直接覆盖中心化端到端流程。

代码 `scripts/deepseek_long_kv_feature_probe_20261117.py`，结果 `runs/deepseek-long-kv-centering-probe-20261117.json`。下一步不应仅继续调整该小样本的中心；需比较能学习 query/key 对齐的方案，先冻结训练与独立评测，再进行遮断原历史的事实换值验证。

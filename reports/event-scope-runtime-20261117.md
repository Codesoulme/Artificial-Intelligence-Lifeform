# 事件时间分类头：隔离读取链对照

## 结论

研究候选不应安装到默认路径。它修正了三条经历中“最初”的选择，但同时把两条原本正确的“更改前”查询拒绝，六条正例的正确数没有提高。小型合成留出集也暴露了误读非查询请求的风险，不能据此宣称具备自然语言时间理解。

## 方法与结果

冻结真实 DeepSeek/孢子集成候选的特征，单独训练四分类线性头：`current / first / previous / abstain`。训练集 96 条、阈值校准集 24 条、测试集 32 条，使用人工构造的问句；姓名和模板按分区分开，但仍属于高度相关的合成数据。测试集 23/32 正确，4 条错误选择具体类别，5 条应读取却暂缓；单一种子。校准阈值约 0.652599。标签顺序不同于原有时间头，禁止作为其替代品加载。

随后在隔离的临时状态中，让两位已登记人物交错获得各三条饮品记录。显式启用实验性身份守卫和 v2 饮品输出头，分别运行原有路径与通过临时补丁接入新分类头的路径。六条正例询问最初、上一次或当前；六条负例涉及否定、假设、多个时间、修改、近名及无关问题。严格核对选中事件及输出值：

| 路径 | 事件正确 | 事件与回答均正确 | 正例拒绝 | 负例进入读取 |
| --- | ---: | ---: | ---: | ---: |
| 原有路径 | 4/6 | 4/6 | 0/6 | 0/6 |
| 新分类头 | 4/6 | 4/6 | 2/6 | 0/6 |

原路径的两条“最初”选中了事件 2、3，即各人的第二条；候选选择了事件 0、1，即预期的首条。两条“更改前”由候选拒绝，原路径选中预期的第二条；两条当前查询两者均正确。六条负例中有五条被候选头暂缓；近名问题被头判成 `first`，最终由独立身份守卫拒绝，不能把它计入时间头的拒绝能力。原路径也拒绝了六条负例。

运行耗时约 181 秒，PyTorch GPU 峰值分配约 3.45 GiB；不是完整系统显存峰值或训练成本。底座、检查点及其他受保护输入的摘要运行前后相同，原有个体状态摘要未变化。系统 Python 使用的是不支持 CUDA 的 PyTorch，首次启动在载入模型前失败；正式对照使用项目 `.venv`，没有覆盖输出或重训候选。

## 限制与下一步

这不是独立验收：人名已登记，事实通过受控数值写入，问法和目标领域有限；时间模式通过测试脚本临时覆盖，不代表默认运行时已经支持该功能。未验证自然语言事实写入、身份认证、故障恢复或长期多主题记录。输出头同样为研究候选。单元测试只验证样本与模板分区、标签顺序及阈值行为，不证明泛化或安全性。

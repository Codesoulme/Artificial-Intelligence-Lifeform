# 交叉训练姓名边界的对照

在前一轮联合片段头的基础上，将 48 个训练姓名各自与原名、后加“子”、前加“小”和三种问法交叉，共构造 488 条训练问题（包括无人及多人问题），冻结底座特征、训练 2400 步。评测使用校验集的另 20 个姓名，在见过和未见过的问法中分别测试见过的姓名变体与未见的“月”“阿”变体；多人问题按是否见过句式分组。训练姓名与评测姓名的完整字符串不重合，所有样例的目标片段均可由词元切分表示。

| 评测组 | 原定位器 | 联合片段候选 |
| --- | ---: | ---: |
| 已登记姓名完整识别，未见问法 | 3/20 | 15/20 |
| 新姓名带见过的“子”，被截成登记姓名，未见问法 | 2/20 | 0/20 |
| 新姓名带未见的“月”，被截成登记姓名，未见问法 | 3/20 | 13/20 |
| 人工多人问题选择单一片段，见过的句式 | 0/8 | 0/8 |
| 人工多人问题选择单一片段，未见句式 | 4/8 | 8/8 |
| 无人问题选择单一片段 | 3/8 | 0/8 |

已见问法中，未见“月”被截为旧姓名 14/20；见过的“子”为 0/20。与未见问法下的结果相近，说明当前候选在这个受控设置中对后缀变化很敏感，换问法也没有消除问题。已见与未见多人句式差异同样值得关注，不能认为它已经学会了多人拒绝。

上轮使用不同训练姓名数、样本数和训练步数，本轮也没有只改变单一变量，因此不能把差异归因于某一训练改动。这里的错误是字符串匹配代理结果，并非实际读错记忆的次数；所有句式和变体均为人工构造，假定近似姓名属于不同人。校验姓名及部分题目已参与以前的开发，姓名子串和底座预训练内容也可能重合；前 21 层与完整模型只在另外十例做过一致性检查。结果不能代表自然对话或独立验收表现。

**判定：不部署。** 下一步应让训练覆盖多种后缀和独立保留的新后缀，并加入多样的多人句式；使用姓名家族和文本分组隔离的校准、测试集，分开评估边界、拒绝、错人读取和正常召回。随后再进行真实路由及语言输出验证。

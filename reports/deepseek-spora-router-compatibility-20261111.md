# Language-to-memory routing after layer replacement

Existing experimental name and time routers were fitted on the original DeepSeek features. We reused those components to check whether their assumptions survive the layer-6/12 replacements. All names, templates and the nine held temporal questions had appeared in prior development; this is not an independent accuracy estimate.

On nine held temporal expressions, a classifier retrained from the original features produced 9/9 classifications for the original model, old paired candidate and diverse-replay pair. For 20 known-name development questions, the existing locator selected the exact name span 20/20 in each mode, while its existing address projection and threshold accepted the correct address 19/20 on the original and 17/20 on each pair. The two additional rejections in each pair still ranked the correct address at both sites but fell below a threshold. Four unbound-name, six no-name and six multiple-name samples were all rejected in this small set; this cannot establish reliable unknown or multi-entity handling. Details and per-question scores are in `runs/deepseek-spora-router-feature-shift-20261111.json`.

We also combined the pre-existing name locator, address projection and time classifier with the SPORA reader for nine held questions about one known entity, plus three negative requests. The controlled state was manually written with coffee followed by water. The model components predicted the name address and time class; experimental code then mapped the class to the two hardcoded event times and page slots. Original layers routed 7/9 positive requests and returned six exact correct answers; both pairs routed 6/9 and returned six exact correct answers. All three negative requests were rejected in each mode. One original-layer query routed correctly but produced a refusal; three positive requests were rejected for missing or fragmented name spans in each pair. These are narrow, reused development cases, not general language routing, autonomous event tracking, persistence, or write validation. Per-query outcomes are in `runs/deepseek-spora-predicted-route-answer-probe-20261111.json`.

## Feature-version guard

`structural_feature_sha256` provides a deterministic fingerprint for a **declared** base, tokenizer/config fingerprint, replacement-checkpoint digests, position lengths and optional tail digests. A `NamedAddressBinding` may now store such a fingerprint; when present, calls require an exact matching variant. Old bindings remain loadable and continue to accept calls that omit a variant declaration, but reject a declared nonmatching variant. This cannot detect a caller that omits or misstates the actual in-memory model, reader, runtime implementation or feature extraction settings; callers must compute and supply truthful component digests. It is not an identity or access-control mechanism.

The existing integrated checkpoint format cannot verify replacement layouts. It now refuses variant-bound name bindings until structural checkpoint support is implemented, rather than silently presenting them as validated. This temporary limitation does not migrate or alter existing individuals. Sixty targeted tests passed, including standalone binding serialization, mismatch detection, preservation of an existing integrated checkpoint after a rejected save, masked attention and native memory integration. The two real-model probes took about 97 and 112 seconds respectively and did not train or modify the individual.

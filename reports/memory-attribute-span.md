# 定位问题片段的记忆路由

在同一人物、经历与话题的成组问题中，读取器需要区分用户索要的是地点、日期、价格或其他属性。使用训练时标注的请求片段学习词元池化后，留出的字段分类正确数从 20/28 提升到 23/28。按预先规定的校准策略，新路由正确放行 7/12 个有记录的问题，并生成 6/24 条严格正确的回答。

训练、校准和测试分别使用 7、3、4 组，共 49、21、28 条。每组共享开头，包含七个不同请求。标注覆盖开头之后的整个请求短语。两组都使用同一个冻结 DeepSeek 候选和线性分类头，训练 400 步。片段组另加一个线性词元打分层，使用分类损失及标注区域的权重质量损失训练。测试时词元打分只看问题内容和冻结隐藏状态。两组使用相同的句首适配器、触发门控、矩阵和双倍读出增益。对象地址由实验提供，已存事实为此前研究矩阵的原值及更正值。

| 指标 | 末尾表示 | 学习片段池化 |
|---|---:|---:|
| 原始字段首选正确 | 20/28 | 23/28 |
| 各自校准后的阈值 | 1.0 | 0.9 |
| 校准后正确读取 | 0/12 | 7/12 |
| 校准后负例误读 | 0/16 | 0/16 |
| 缺失属性明确说明 | 0/12 | 6/12 |
| 普通问题继续使用默认解码 | 0/4 | 2/4 |
| 完整回答严格正确 | 0/24 | 6/24 |
| 原值与更正均严格正确 | 0/12 | 3/12 |

阈值按校准集优先避免错误读取。末尾组因此选择了全回退，生成对照的差距包含校准行为。固定在 0.9 时，从已保存的留出分类分数重算，两个路由分别正确放行 5/12 和 7/12，均未错误放行。该共同阈值只补充比较分类决策，未用它重新生成末尾组的答案。片段组最高权重词元在 28/28 条中落在标注区域内。标注区域较宽，这项结果不能区分模型是定位了精确疑问词，还是学会了关注共有题型中的后半段。

片段组正确放行的 7 个问题中，有 2 个在原值和更正两侧均未触发事实注入，分别生成拒答和重复词元。一个地点问题生成了正确的两个地点，但“抵达”未列入冻结的地点谓词规则，故两条均未通过严格评分。另一个职业问题虽然注入了正确值，句首却声称无法提供确切信息，也没有计入严格通过。两条普通问题因置信度不足转成澄清。

实际评测共 80 个组合，保存了生成词元、分类概率、校准网格、计划和路由权重。生成前重载路由权重，运行后核对组合覆盖、逐行结果、文件摘要及保护输入。约耗时 97.2 秒，PyTorch 峰值显存分配约 3.55 GiB。结果位于 `runs/deepseek-memory-attribute-span/`。本轮采用手写、按问题开头分组的留出样本，待验证请求片段位于句中或句首时的表现。优先继续定位生成门控在已有可读记录时为何不触发，并加入真正多轮输入的对照。

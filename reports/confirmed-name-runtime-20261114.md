# 显式姓名确认与临时记忆读取

## 实验范围

新增研究用入口：未提供姓名时先要求输入；输入没有登记时直接拒绝；已登记时，只有当前问题、用户输入的完整文字、模型选中的片段及其登记地址相互一致，才允许现有读取流程继续。每次读取都要重新提供姓名，确认不会保存。该入口是可选的，原默认入口不受影响。

在旧的替换层运行路径中，临时登记“小林”和“小林华”，分别向独立地址写入人工指定的测试值。以下测试使用实际模型推理和临时状态，记录进入记忆状态检查和读取函数的次数；姓名、事实和问句均为开发数据。

| 场景 | 结果 | 状态检查 / 读取次数 |
| --- | --- | --- |
| 未输入姓名 | 要求输入 | 0 / 0 |
| 输入未登记姓名 | 拒绝 | 0 / 0 |
| 询问小林，输入“小林” | 读取地址 6，输出“水” | 1 / 1 |
| 询问小林华，输入“小林华” | 模型选短名，确认不一致，拒绝 | 0 / 0 |
| 询问小林华，误输入“小林” | 错误读取地址 6，输出“水” | 1 / 1 |

最后一行是实际反例：人为确认和模型同时使用错误短名时，仍会读取错误对象；它不是实际用户数据泄露。系统也不能因此证明输入者身份或授权、区分同名人物、识别别名、判断代词指向或检测用户误输入。要继续研究更明确的身份表示、歧义澄清和交互体验，不能将这一实验机制当成安全系统。

这次只覆盖一个真实模型短名及其人工构造长名，没有测试真实用户、多轮、历史读取、并发或持久恢复。模型仍存在语言能力受损与错误路由问题；以上结果不能外推到保留原语言层的新候选，也不能视作正常聊天能力。临时事实是数值写入而非自然语言学习。

## 验证与产物

`spora/confirmed_name_read.py` 为可选实验入口；`spora/identity_read_guard.py` 将原片段提取逻辑单独暴露，原指纹判断保持不变。`tests/test_confirmed_name_read.py` 覆盖未确认、未登记、不同问题及地址、完整长名与片段不一致、误确认反例，以及调用现有运行流程时读取前拒绝。原有两组保护测试也通过。

真实路径脚本为 `scripts/deepseek_spora_confirmed_name_runtime_probe.py`，逐条结果保存在本机 `runs/deepseek-spora-confirmed-name-runtime-20261114.json`。运行约 147 秒，显存分配峰值约 3529 MiB；底座和检查点前后校验一致，原状态与临时状态未因读取改变。没有修改正式个体。

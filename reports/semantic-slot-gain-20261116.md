# 语义槽增益桥验证

## 发现

直接容量扫描显示，值的词向量本身可以被冻结语言头解码，但需要较大的隐藏残差。增益为 `32` 时，两个留出人物的 8 个已见值首词均为目标，4 个未见值也均为目标；低增益时大部分目标不进前十。把槽残差持续施加到缓存步会导致值重复输出，因此读取接口改成每次 `use_slot` 上下文只消费一次，后续 token 回到原语言头。

## 可训练原型

在此容量上限上增加可训练的恒等增益路径，初始化增益 `32.0`，保留低秩修正分支。只用首个回答词的交叉熵训练 384 步，增益收敛到约 `32.65`，独立进程重载后结果如下：

| 条件 | 首词严格命中 |
| --- | ---: |
| 留出人物、训练值 | 8/8 |
| 留出人物、未见值 | 4/4 |
| 独立重载总计 | 12/12 |

普通问题在有无槽两次调用中保持逐词元一致，底座摘要也未变化。

## 这代表什么

这证明当前底座具备一条可泛化的“语义向量槽 -> 首个回答词”读取通道；它比此前随机初始化的低秩读取适配器更合适作为孢子记忆的语言接口。它还没有证明完整回答质量：使用一次性槽读取后，底座可能继续列举或解释，严格完整字符串在本轮只命中少数样例。后续应训练回答边界或让槽参与短期 KV/隐藏状态，而不是继续提高增益。

## 尚未解决

- 写入端仍由实验直接提供值 token embedding，没有自然语言事实解析或身份路由。
- 槽是临时向量，尚未接入增量保存、崩溃恢复、纠错和睡眠巩固。
- 只验证单个“人物喜欢饮品”关系，没有多事实并存、未知事实拒答和普通多轮对话。
- 首词命中不能等同于完整中文聊天能力，也不能证明主观意识。

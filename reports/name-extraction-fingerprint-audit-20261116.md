# 模型姓名提取与登记表对照

## 方法

在隔离进程中加载 DeepSeek-R1-Distill-Qwen-1.5B 冻结底座，向模型提出姓名提取任务，要求只有一个明确人物时返回完整姓名，其他情况返回 JSON 空值。使用人为关闭思考段、贪心生成、最多 48 个词元；这是借助提示词的诊断任务，不是模型自主身份识别。

临时创建 `IdentityFingerprints` 张量模块，显式登记五个合成姓名；模型输出解析后必须是原问题中唯一出现的字符串，才送入登记表查询。共 30 个人工问题：8 个已登记人物、10 个相近姓名、4 个其他未登记姓名、4 个多人问题及 4 个无人问题。多人问题按拒绝单人读取处理。

比较两种解析方式：严格方式只接受完整 JSON 对象；宽松方式允许解释或代码块中恰好有一个可解析对象，再按相同规则检查字段和原文子串。两者使用完全相同的模型输出，宽松方式是事后离线重算。子串存在不能证明姓名完整，宽松解析也不是安全边界。

## 结果

| 检查 | 严格解析 | 宽松解析 |
| --- | ---: | ---: |
| 已登记人物正确提取并匹配 | 0/8 | 2/8 |
| 相近姓名正确完整提取 | 0/10 | 2/10 |
| 相近或其他未登记姓名误匹配到登记项 | 0/14 | 0/14 |
| 多人问题错误接受单人读取 | 0/4 | 0/4 |
| 无人问题错误接受单人读取 | 0/4 | 0/4 |

严格解析下，已登记人物的八次输出中三次不是纯 JSON、五次为空；宽松解析后两次正确匹配，其余六次为空。未登记问题未被误接受，主要因为大量输出为空或无法解析，不能当作姓名提取可靠的证据。宽松解析还将一条问题中的“里阿岚青”当成姓名，而真实标注是“阿岚青”；由于该字符串未登记，最终仍被拒绝。

独立单元测试展示了另一种风险：在“小林月”的问题中，如果模型只输出“小林”，原文子串检查和登记表都会接受错误人物。本轮 30 条模型生成中未观察到该误接受，不代表它不会发生。临时登记表保存后在另一个进程恢复，五个登记项均能查回，“小林月”查询为空；这只验证表的恢复，不验证语言提取的恢复或实际记忆读取。

## 限制与判断

当前提示和模型配置下，正确人物召回过低，不能接入正式读取。严格格式拒绝及宽松格式比较只用于研究，前后文字中出现误导性对象、同名、别名、姓名截断和提示注入均未得到解决；登记表不是现实身份认证，姓名摘要也不是加密保护。

样本小且人工构造，与底座预训练或本项目早期材料的重叠未知；没有进行训练、真实个体记忆读取、端到端对话、不同提示及采样策略的对照。底座摘要在运行前后核对一致。生成与基础检查约 117 秒，CUDA 峰值分配记录在结果文件中；解析重算不重新调用模型。

代码及测试为 `scripts/deepseek_spora_name_extraction_audit.py`、`tests/test_name_extraction_audit.py`；模型原始回答、解析重算及临时登记表位于 `runs/deepseek-spora-name-extraction-audit-20261116/`。

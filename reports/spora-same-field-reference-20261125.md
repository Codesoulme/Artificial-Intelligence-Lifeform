# 同字段草稿的跨事项绑定与自动跨度回放

此前的独立引用头可以区分同一事项内的时间、地点等不同字段。本轮将两个待改草稿放在不同事项中，且每对草稿使用同类字段。训练 2,160 个决策，校准 960 个。独立留出 1,536 个决策，其中 512 个应提交。保留事项明确、仍在商议和指向不清的对照，并交换两条草稿的位置。放映场景只在留出出现。DeepSeek 底座、确认动作头和个体冻结。匹配时分别编码用户指向句和候选记录，候选侧比较「事项加字段」与「仅事项」两种表征。 [前轮分开训练](spora-separate-revision-reference-20261125.md)

| 留出指标 | 原头，事项加字段 | 同字段续训，事项加字段 | 同字段续训，仅事项 |
| --- | ---: | ---: | ---: |
| 明确指向题中，正确草稿排首位 | 480/1024 | 688/1024 | 640/1024 |
| 涉及未见放映场景时，正确草稿排首位 | 168/384 | 200/384 | 200/384 |
| 应提交时，正确写入事项与字段 | 0/512 | 0/512 | 0/512 |
| 写入错误事项 | 0 | 8 | 8 |

两种续训的 8 次误写集中在同一种混淆。模型把备货交接判成维修取件，分别写错 4 条人员和 4 条地点记录。这些错误都出现在本来应该提交的回合。冻结动作头接受了全部 512 条应提交确认。只用事项名称降低了正确排序，单纯去掉共有字段未解决引用绑定。给定完整草稿时，校准规则在留出上仍无法得到正确提交。

## 接入自动跨度

将同一留出集两条草稿分别写成含有旧值和备选值的原话。使用已有的冻结跨度写入器，从 34 条去重原话自动选字段、复制完整候选，再接入相同的确认和匹配链。写入回放使用两个各自独立的会话记录。已知事项的前提下，写入器同时找准字段和完整新值 14/34。接回实际匹配头后，完整提交仍是 0/512，当前瓶颈首先是跨事项指向。

独立重载时另用正确指向做反事实回放。34 条原话的字段均选对，只有 14 条完整值正确，其中 9 条误取旧值、4 条截断新值、7 条选到其他文本。固定正确指向后，自动跨度在 512 条应提交决策中能正确写入 208 条。剩余 304 条未得到正确记录，其中可能包括写回原值。给出正确字段的结果也是 208/512。由此把跨事项绑定和完整跨度两个瓶颈分开量化。

下一轮需要用原始登记发言建立事项向量，再让后续引用与这些向量对照学习。尤其应覆盖同类内容处于不同事项的成对场景，避免用品交接和维修取件只因共享词而互换。引用成功后，还要继续核验自动跨度对完整记录的影响。当前实验预先给出了事项清单和草稿字段，同一事项内的多条同字段草稿也需另测。

两次训练及评测分别约 86 和 88 秒。独立重载分别约 87 和 88 秒，逐题复现分数和两条记录的最终状态。四次运行的 32 条受控持久读取均与父实验逐条一致，个体摘要一致。15 项相关单元测试通过，另核对了交换草稿顺序、指向不清和暂缓时的跨事项状态写入行为。

## 复现

```powershell
$env:OMP_NUM_THREADS = '2'
$env:MKL_NUM_THREADS = '2'
$sporaSplit = 'runs/spora-recurrent-split_gated_block_delta-warm-v1'
$sporaArgs = @(
    'runs/spora-composition-late-gates-20-23-24-v1/candidate.pt',
    'runs/spora-separate-revision-reference-v1',
    'runs/spora-described-revision-span-v1',
    'runs/spora-same-field-reference-v1',
    "$sporaSplit/layer-19", "$sporaSplit/layer-22"
)
.\.venv\Scripts\python.exe -u -m scripts.train_spora_same_field_reference @sporaArgs
.\.venv\Scripts\python.exe -u -m scripts.train_spora_same_field_reference @sporaArgs --verify
```

仅事项的对照将输出目录换为 `runs/spora-same-field-topic-key-v1`，两条命令都添加 `--topic-key`。独立重载同时生成 `candidate-audit.json`，记录真实候选提取结果及给定正确指向时的回放。

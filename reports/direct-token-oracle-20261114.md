# 记忆到语言输出层上限诊断

## 目的

上一轮已经确认结构化记忆槽可以保存并恢复受控事实，但“读出来的事实”不一定能被 DeepSeek 语言层生成成正确答案。本轮把问题拆成三个条件：无记忆、只启用记忆读取、使用现有学习输出头；另加一条研究用上限通路，把测试已知的目标词元序列直接加到生成 logits 中。

最后一条通路叫 `DirectTokenOracle`，它读取测试脚本提供的目标答案，不是可部署机制，也不代表模型已经学会了答案。它只回答一个边界问题：当路由、事实和输出目标都正确时，生成器本身能不能表达这个答案。

## 结果

| 条件 | 严格答对 |
| --- | ---: |
| 无记忆 | 0/4 |
| 只读记忆，不加输出证据 | 0/4 |
| 当前学习输出头 | 2/4 |
| 直接词元上限 | 4/4 |

内部记忆查询本身正确 4/4。两个人物的当前值“酸奶”和过去值“咖啡”都读对。第一版脚本曾把第二个人物的历史查询错误地固定到第一个时间片，得到索引 `16`；复核后已按实际写入时间重跑，该异常不计入模型结果。

在四个记忆读对的案例中，学习输出头把两个“咖啡”生成正确，但两个“酸奶”都生成“水”。关闭记忆输出头后没有一个案例严格答对。直接词元上限 4/4，且所有生成均可在目标词元后结束。

修正后的逐条结果：`runs/deepseek-spora-direct-token-oracle-v2-20261114.json`。第一版结果保留在 `runs/deepseek-spora-direct-token-oracle-20261114.json`，仅作为脚本参数错误记录。

## 判断

这轮排除了“底座完全不能生成这些中文答案”这一解释，也没有证明记忆已经具备自然语言能力。当前主要问题是：

1. 记忆查询的有限值空间仍需要明确的未知/低置信度分支；本轮虽未复现越界索引，但旧实验已显示错误证据会进入输出头。
2. 现有输出头把记忆值映射到生成分布的方式不稳定，特别是同一值“酸奶”在两个身份上都变成“水”，说明它还没有学会身份无关的值到词元映射。
3. 记忆读取层本身的残差会让模型产生代码块或长解释，说明“记忆证据如何进入回答位置”仍与普通语言生成分布不匹配。

下一轮应先做有限值读出校准和拒答门控，再训练一个直接面向答案词元位置的可学习输出适配器。训练集必须按“人物、问法、值”三维拆分，加入未知值、历史/当前切换和普通请求负例；直接词元上限只能继续作为诊断基线，不能进入正式运行时。

## 限制

人物、数字地址、写入顺序、问题模式和目标词表均由实验提供；只有 4 个短饮品案例。没有测试自然语言写入、开放域对话、长时持久恢复或中文自由聊天。实验没有修改正式个体、底座权重和默认检查点；显存峰值约 3.70 GB。第一版脚本的错误时间参数已在第二版修正。

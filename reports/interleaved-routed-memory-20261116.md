# 多人交错状态的自然问句路由开发检查

## 方法

在临时进程中加载现有集成候选（DeepSeek 底座、孢子替换层、原生记忆读取器、输出适配器和路由器），创建隔离的空个体状态。测试程序先对八个已绑定名字写入初始事实，再对同八人写入更正，共 16 次受控事件。写入时由程序指定名字对应的地址、有限饮品值、来源和事件顺序；没有测试从自然语言自主写入。

读取时，程序只给 `SporaChat.answer()` 问题文本。16 个正例均为八人的“以前/现在喜欢喝什么饮料”；判定路由正确要求模型接受问题、人物地址正确、时间意图正确，历史问题还须选中对应事件时间。回答严格正确还须整个短答案匹配期望饮品，不能因为偶然给出相同词但路由错误而算成功。另有六个负例：两个未登记人名、两个与“小林”相似的人名、一条否定查询指令和一条普通鼓励请求。

两次进程使用相同源文件摘要与相同问题/状态。第二次显式启用已有 `IdentityReadGuard`，在临时状态外用实验提供的八个姓名与地址创建精确指纹登记。它是规则校验，不是神经自主学习，也不鉴别人类身份。

## 结果

| 指标 | 默认路由 | 手动姓名指纹校验 |
| --- | ---: | ---: |
| 正例人物、时间和事件路由正确 | 12/16 | 12/16 |
| 正例路由正确且回答严格匹配 | 9/16 | 9/16 |
| 负例拒绝 | 4/6 | 5/6 |
| 负例错误接受 | 2/6 | 1/6 |

默认条件下，四个当前问题被 `not_confident_read_intent` 拒绝；其余 12 个地址与时间均正确，其中三条虽然路由正确但回答了错误饮品。两个普通未登记人名被拒绝；“小林林现在……”和“小林子以前……”均错误地读到小林的地址 6，分别回答“咖啡”和“茶”。否定查询及鼓励请求被拒绝。

手动指纹校验拒绝了“小林林”，但“小林子以前……”仍被当作小林读出“茶”。已知该校验器只核对定位器选出的文本，定位器截断、同名或别名均可造成错误；这次没有单独记录选中片段，因此不能断定本次误读的具体原因。该校验器仍是显式实验选项，不能作为一般身份识别或访问控制。

默认运行约 196 秒，指纹校验约 168 秒，两次峰值显存均约 3.82 GB；计时包含加载及校验，不是公平性能基准。源码与底座、集成候选和各路由头在运行前后按摘要校验一致；使用临时工作路径，没有创建或改写工作个体。

## 边界与后续

这比直接提供地址的多人检查更接近真实问题，但仍是小规模、已使用过的名字、有限饮品、固定短问句和直接写入事实，不是独立开放中文聊天测试。六个负例不足以估计整体误归属概率。上一轮 `16/16` 使用直接地址与另一条输出路径，本轮 `9/16` 经默认路由及集成输出适配器，两者不是仅改变路由的严格对照。

下一步需把身份片段完整性作为单独问题处理，使用未参与设计的人名、相似名、同名和自然句子进行匹配对照，测量漏读和误读；同时针对路由正确但答案错误的三例，分离原生记忆读取与输出适配器。没有通过独立评估前不得将默认路由视为可靠身份边界。

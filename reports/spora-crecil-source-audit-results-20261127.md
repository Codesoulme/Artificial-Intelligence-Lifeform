# CRECIL 来源及标注核查结果

日期：2026-11-27。依照[计划](spora-crecil-source-audit-plan-20261127.md)，检查 [CRECIL 固定提交](https://github.com/bistu-nlp-lab/CRECIL/tree/68c922c003e19d68a36b63752cba4ef801b82933) 的训练集、开发集、说明和数据生成代码。全部所取文件的 Git blob 哈希与该提交的文件树一致；仅在 `runs/research/crecil-source-20261127-v1/` 保存数据和汇总，未下载官方测试集，也未执行来源仓库的 Python 或反序列化 pickle。

## 关键发现

1. **不能直接拿其 `unanswerable` 标签训练“当前资料无依据”。** [作者的三元组生成代码](https://github.com/bistu-nlp-lab/CRECIL/blob/68c922c003e19d68a36b63752cba4ef801b82933/My_home_data/exportCRT.py) 收集场景中的发言人与角色指代，将其映射到全局人物，查全局人物关系表；表里没有该有序人物对且不是同一人物时，就赋予 `unanswerable`。这是全局关系表中未找到关系，不等同于人工确认当前片段无法回答。相反，表中存在的关系也不保证该片段本身明确说明了关系。
2. 训练集 482 段、13,832 条话语、35,450 条人物对关系记录，其中 11,039 条为 `unanswerable`；开发集 116 段、2,773 条话语、7,422 条关系记录，其中 2,256 条为该标签。原始 README 展示的含角色指代第三部分的数据格式，与实际 `Final_Data` 每条只有话语列表和关系列表不同，不能把这两个已发布文件直接当作带证据跨度的数据。
3. 按完整话语列表精确比较，训练与开发之间没有完全相同对话；但开发集有 5,215 个不同的有序“人物表示—人物表示—关系编号”三元组，其中 2,701 个也在训练集出现。人物表示包含作者生成的场景内 `S N` 等代号，不一定代表同一人物；这一重合统计只是识别符级别的提示，不能解释成真实人物关系泄漏率，也不排除近似对话重复。
4. [官方划分脚本](https://github.com/bistu-nlp-lab/CRECIL/blob/68c922c003e19d68a36b63752cba4ef801b82933/Final_Data/shuffle_data.py) 对中、长对话桶取切片时使用短桶长度计算边界，而且随机打乱没有固定种子。不能仅根据注释和脚本复现实际文件；已发布 train/dev 是本次权威输入。实际话语长度范围分别为 1–70 和 1–46，说明两个已发布划分长度分布不同；成因仍需更完整数据才能确认。

## 来源与边界

作者说明数据来自《我爱我家》剧本，仓库有 Apache-2.0 许可证；这并不单独确认底层剧本所有权和再次发布权限。此次只做本机非发布的结构研究，未把剧本文本上传。训练集 SHA-256 为 `8b197f6a857130577462813c28e2f8229f945c419ed18340a9a6270ed643a351`；开发集为 `f3eef68ed89379e6d3acb4e685d557bf4bdaadad45dd15795141f9e86f8e764a`。汇总脚本为 [audit_crecil_20261127.py](../scripts/audit_crecil_20261127.py)；它只统计并不验证标注含义或关系事实。

训练关系中，有 4 条 `x` 和 4 条 `y` 没有以完整字面字符串出现在对应话语列表，开发集均为 0。字符串存在不等同于指代解析正确，更不等同于关系有文本证据。

## 决策

CRECIL 可用于研究中文多人指代和关系建模，但不能直接承担本项目的“仅根据对话记忆判断是否有证据”验收，更不能直接把缺省关系当真实否定。下一步优先寻找带证据跨度、无答案标注且许可清晰的对话资料；若没有充分覆盖的人物缺席案例，设计人工核查的配对开发样本，并保留独立来源与正式测试。整个方案还需最终对比原底座和嵌入孢子结构后的实际生成及持久化。

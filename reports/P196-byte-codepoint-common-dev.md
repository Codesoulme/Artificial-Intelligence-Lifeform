# P196 字节与字符接口共同文本诊断

针对 P157 的跨单位 NLL 不可直接比较问题，使用两个已有训练检查点、同一父个体及 P18 开发分区，按相同的原始中文片段计算总负对数似然，再除以相同的 UTF-8 字节数和 `ln(2)`。没有训练，也没有读取测试正文。输入文件摘要、逐文档结果及局限保存在 `runs/p196-byte-codepoint-dev-20261109.json`。

8 篇开发文档共 172 个 Unicode 字符、484 个 UTF-8 字节；训练侧构建的字符词表无法表示其中 27 个字符，8 篇均有未知字符。因此按未知字符切开，两个模型仅对相同的 24 个可表示连续片段、合计 403 字节评分，排除未知字符及 EOS。每段重新从 BOS 开始，各接口按最多 128 个各自词元分窗，目标位置各计一次。

| 接口 | bits / 原文 UTF-8 字节 |
| --- | ---: |
| 字节 v2 | 4.047 |
| 字符 v2 | 2.997 |

在这些很短的已覆盖片段上，字符接口归一化损失较低，与直接比较每目标 NLL 得出的印象不同。这不是完整文本似然：未知字符被排除、上下文被切断，样本仅 8 篇短合成文本；两条路线训练目标数、总算力及词元上下文对应的字符范围不同，也没有多种子重复。不能据此推断一般中文或聊天表现，更不能得出架构优劣的因果结论。字符词表的未知字符率是此样本的观察值，不可外推到其他语料。

原个体文件、两个检查点、词表及清单摘要在评测前后不变，冻结状态摘要不变。评测并未改写记忆，测试不包含语义能力或长期记忆对齐检查。

复现：`python -m scripts.compare_byte_codepoint_dev --individual checkpoints/individual-prechinese-v3.pt --byte runs/p154-context-long-ablation-20261109/v2/checkpoint.pt --codepoint runs/p157-codepoint-train-retry-20261109/checkpoint.pt --vocab runs/p157-codepoint-vocab-20261109.json --manifest runs/chinese-curriculum-v2/manifest.json --output runs/<new-result>.json`。开发评测使用这些已有检查点所绑定的清单与词表；输出文件必须不存在。

下一步应以训练侧数据构建可回退的表示方式，或选择足够覆盖的训练词表，并在相同开发文档上报告未知字符、训练计算和独立生成表现；应先保证预处理和数据分组质量，避免只针对这 8 条开发文档选词表。

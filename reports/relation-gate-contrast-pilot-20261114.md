# 饮品关系判别对照

使用冻结 DeepSeek/SPORA 特征，训练单独的线性二分类头，判断请求是否适合查询有限饮品名称。该分类与现有意图头、身份识别及最终生成完全隔离，没有改变默认路由。两版使用同样的校准组与开发题，阈值都依据各自小型校准负例选取；第一版含 108 条合成样本，扩充版增加属性、推测反例后共 140 条。训练、校准和开发三组的人名及句式只在本实验内部不重叠，部分人物与语义可能在项目其他实验出现过。

| 开发题类别 | 数量 | 第一版放行 | 扩充版放行 |
| --- | ---: | ---: | ---: |
| 应读取的饮品名称 | 6 | 5 | 3 |
| 颜色、味道或容量 | 6 | 3 | 3 |
| 否定请求 | 4 | 0 | 0 |
| 写入或删除 | 4 | 0 | 0 |
| 假设或推测 | 4 | 2 | 0 |
| 推荐请求 | 4 | 0 | 0 |

表中只有名称查询应放行，其余应拒绝。第一版出现错误后，我们查看了开发题类别并补充相关训练反例，因此扩充版的这组题不再是未参与调整的测试。扩充版拒绝了两条曾误放行的推测题，但仍错误放行两个人物的颜色请求及一条味道请求，还额外拒绝了两条名称查询。其校准正例通过数也从 4/4 降至 2/4。每组仅有少量人工样本，无法估计真实分布上的错误率。

这次结果表明当前词句特征上的线性头存在明显混淆，单纯增加这一批相似反例没有同时解决关系识别和召回。两版均未进入真实路由或生成阶段，更不能声称具备身份认证、自然写入或开放语义能力。保留候选仅供研究，不应启用；后续可研究将关系、意图与实体分别建模，并在新的、未参与这一轮选择的真实表达上进行校准和端到端对照。

底座、原检查点和个体状态均经摘要核验未变。第一版耗时约 119 秒，扩充版约 107 秒，显存分配峰值均约 3,529 MiB。脚本：`scripts/deepseek_spora_relation_gate_pilot.py`、`scripts/deepseek_spora_relation_gate_v2_pilot.py`；逐条结果和候选在对应的本机 `runs/deepseek-spora-relation-gate*-pilot-20261114/` 目录。

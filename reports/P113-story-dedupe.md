# P113 候选故事内部近重复分组

状态：候选未训练。工具只读取明确指定的候选 JSONL，不读取其他数据，也不调用训练程序；与 P112 进程没有依赖或共享输出。

## 使用

```powershell
python -B scripts/p113_story_dedupe.py --input D:/path/candidate.jsonl --output D:/SPORA/runs/p113-example
```

输入每行须为 JSON 对象，`text`、`group`、`sha256` 均为字符串。普通输入的 `sha256` 是原文 UTF-8 字节摘要；P112 格式用 `source_original_sha256` 保存原文摘要、`sha256` 保存 NFKC 后去空白及转小写的文本摘要，工具会同时核验两者。其他字段原样保留。空行、格式或校验错误会失败。输出目录必须在 `runs` 下、父目录存在且目标不存在，采用独占创建；失败时可能留下不完整目录，另选新目录重试。程序不自动删除任何目录。不得将测试或开发集作为输入；使用者需确认来源确为候选训练故事。

执行次序：先以原文完全相同和规范化前 96 字符合并；规范化是 NFKC、casefold、删除所有空白，短文本取全部规范化内容。不同原文即使前缀相同，也分别参与后续索引，以免丢失连接。提取 NFKC 后汉字序列（含所列扩展区）中的连续五字集合，非汉字先被移除；不同故事的真实集合 Jaccard 达到阈值（含等号）才建立近似边。使用固定哈希及 32 项签名，8 个 band、每 band 4 项生成候选对；最后合并所有已确认边的连通分量，代表为输入中最早的记录，输入顺序因此属于结果定义。

默认 `--threshold 0.8`；高频特征的文档频数超过 `max(--min-df-cap, floor(--max-df * 不同原文数))` 时不用于索引，默认分别为 100 和 0.1。涉及被移除特征的记录及其整个连通组被隔离。默认 `--max-bucket 200`，`--max-pairs 1000000`；过大桶或超过全局比较预算的桶不做截断抽样，而将所有成员所属组隔离，并记录完整成员行号。少于五个汉字、无可索引特征的记录也隔离。预算按排序后的桶保守计算，可能把部分本可处理的桶送审。所有限制均可用同名命令行参数调整。

输出：`candidates.jsonl` 为非隔离组的代表；`quarantine.jsonl` 保留隔离组全部原记录；`groups.json` 列输入行号、代表、状态和原因；`unchecked_buckets.json` 列每个未检桶的成员与原因；`summary.json` 记录参数、数量、输入与输出摘要和局限。无需原文即可检查组信息，但原始输入必须保留才能通过行号追溯。隔离范围只覆盖已知资源限制，不能保证发现所有漏检。

局限：LSH 的召回不是 100%，相似对可因签名不碰撞而漏掉；语义改写未必共享足够字面片段，阈值也会带来误合并和漏合并。传递闭包内两端可以低于阈值。该工具不是完整语义隔离或全对比较，不能据此推断与任何其他数据集之间的隔离。整体仍将记录、特征集合、桶及受限的候选对保存在内存；桶和比较数限制不构成全局内存上限，较大输入应先在实际机器评估内存。

## 验证与合成压测

`python -B -m unittest discover -s tests -p test_p113_story_dedupe.py -v`：7 项通过，覆盖传递关系及非代表桥接、阈值等号、短文本、频繁特征、未检大桶、比较预算、覆盖保护与摘要校验。没有读取受保护集。

随后修正 P112 数据的摘要字段兼容性，并增加测试：原文和规范化摘要任一不符均拒绝。使用 P112 的 160 条训练侧质量样本做格式衔接检查，160 条均可读取，未触发已检测的组内重复及隔离；这个小样本不能代表未来 20 万条数据的重复率或内存使用，未对其进行训练。

压测使用随机种子 113 生成的 10,000 条、每条 96 个汉字的纯合成故事；其中 1,000 对人为构造为仅替换四字的相似文本。默认配置，第二次运行实际进程 CPU 17.91 秒、墙钟 18.12 秒，Windows 进程峰值工作集 272.32 MiB、峰值提交 266.28 MiB（包括 Python 进程开销，不包括首次合成文件生成）。验证 996 对、合并 996 对，得到 9,004 组，零隔离、零未检桶；未找到 4 对体现该数据上的 LSH 漏检，不代表真实语料召回率。两次运行候选、隔离、组元数据及未检桶四份文件的 SHA-256 完全一致。机器负载、文本长度和数据分布都会改变性能。

压测数据、两次输出和测量结果在 `runs/p113-synthetic-10k-20261109/`，其中 `benchmark-verified.json` 为正确的 Windows 进程内存计数结果。

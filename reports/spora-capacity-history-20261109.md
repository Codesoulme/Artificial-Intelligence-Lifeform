# 有限容量与历史保持实验

在原模型参数和地址基底上建立三个空状态，分别使用随机种子 4615、4616、4617。每条经历先观察 64 个不同对象，再对其中对象进行 128 次纠正，均为可信直接观察。原个体文件和原始状态均检查未被修改。详细结果：`runs/spora-capacity-history-retention-20261109.json`。

三个状态在 192 条事件后，当前值均为 64/64，按实际对象及真实事件序号读取历史均为 192/192；较早检查点也全部正确，未观察对象未被误判为已知。这是有限任务，不能证明未发生事件、自然语言历史查询或其他个体的可靠性。

状态包含的标量数，不包含模型参数和序列化开销：一页、最多 64 事件时为 51,300；两页、80 至 128 事件为 86,130；三页、192 事件为 120,960。当前矩阵为固定的 16,200 个标量，历史页与来源状态随页数增长。每个检查点仅采样八次 CPU 单条查询，波动较大，不能作为生产延迟结论。

该结果只覆盖 64 个键、16 个值、三个共享参数和基底的状态；没有验证崩溃恢复、开放实体、来源和语言接口。后续应检查错误对象及未发生时间是否会产生虚假记忆。

补充负例：对每条真实事件，把对象换成相邻编号并保持时间不变；最终三条经历分别有 1/192、0/192、1/192 被错误判为已知。较早检查点会重复检查部分同一事件，不能当作独立样本。对已分配但尚未写入的下一时间点，每次检查全部 64 个键，均未误判；页面写满时没有可测的已分配未来时间。结果位于 `runs/spora-capacity-history-negative-20261109.json`。这证明至少存在虚假历史读取，须在接入语言查询前解决或可靠识别；相邻编号负例也不能覆盖所有错误对象和时间。

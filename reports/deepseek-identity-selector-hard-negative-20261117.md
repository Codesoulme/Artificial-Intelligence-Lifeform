# 人工近名困难负例训练

在 [人工姓名片段选择器](deepseek-identity-selector-oracle-span-20261117.md) 上，将每个训练姓名加“甲”构造相近姓名。已知任务同时提供原名和近名作为候选；未知任务交替询问近名而候选含原名、或询问原名而候选只含近名。另有普通候选作干扰，训练仍为 2,400 个合成任务。留出近名使用不同后缀，姓名边界与记录身份仍由实验人工提供；没有自动从对话抽取人物。

| 开发案例 | 原人工片段训练 | 加困难负例 |
| --- | ---: | ---: |
| 留出姓名已知查询正确 | 10/24 | 10/24 |
| 留出姓名已知查询错选 | 4/24 | 7/24 |
| 留出姓名已知查询误拒 | 10/24 | 7/24 |
| 留出姓名未知查询误选 | 6/24 | 14/24 |
| 四组相近姓名、各两问，误选 | 4/8 | 3/8 |

训练人物的已知查询正确从 31/48 到 42/48，而训练人物未知查询误选从 24/48 到 26/48；模型倾向更频繁地选取记录。近名少一次误选不足以抵消普通未知组恶化。三个普通问题均选无匹配，但这些问题仍使用句末表示，不能作为广泛无关输入测试。

两次使用同一底座、网络、人工边界、训练步数和开发候选组合，但训练数据与采样分布不同，且新增姓名增加特征提取计算；不是等数据或等计算对照。训练与开发例均很小、由程序构造、被前期查看，只有一个训练种子；生成姓名的规则不能代表自然姓名、别名或同名。无匹配选择也不保证底座会诚实拒答。

候选没有接入记忆生成，也未验证身份边界自动识别、事实存取、多主体上下文、普通对话或持久性；正式个体未改，底座散列前后相同。运行约 110 秒，PyTorch GPU 峰值约 3.32 GiB。4 项单元测试检查困难样本标签、选择器及词元边界；困难样本构造在实验完成后提取为独立函数，保持相同采样操作，尚未再次运行整轮训练验证逐项复现。

入口 `scripts/deepseek_identity_selector_hard_negative_20261117.py`，逐项结果和隔离候选 `runs/deepseek-identity-selector-hard-negative-20261117/`。这一方案不部署；下一步需单独冻结未知样本比例和独立阈值校准，增加真实语境及边界错误，并核查能否在不严重牺牲已知召回的前提下降低错读。

# 原语言层请求门控试验

为上一轮原语言层姓名路由训练两个独立线性头：一项判断是否恰好一个人物，另一项判断是否请求读取饮品偏好。多人记忆请求在训练标签中属于“读取”，但不属于“单人”；只有两项均通过才允许后续单人路由。两个头使用冻结的原版语言层特征；阈值分别由少量校准负例选取。

对上一轮已查看的姓名路由结果做离线组合，未重新执行姓名定位、记忆读取或生成：

| 类别 | 题数 | 原姓名与指纹结果放行 | 加两个门控后放行 |
| --- | ---: | ---: | ---: |
| 已登记人物 | 16 | 正确地址 6 | 正确地址 5 |
| 多人问题 | 2 | 误放行 2 | 误放行 0 |
| 相似长姓名 | 8 | 误放行 0 | 误放行 0 |
| 未知姓名 | 4 | 误放行 0 | 误放行 0 |
| 无人物 | 2 | 误放行 0 | 误放行 0 |

额外八条本轮手写挑战题中，一条多人问题和一条推荐请求被两个门控放行；颜色、否定、写入、推测、普通问题各一条及另一条多人问题被至少一个门控拒绝。这八条没有接到姓名路由，不能当作最终误读次数。两条多人中只拦下一条，说明不能凭上表的旧题结果认定多人问题解决。

训练、校准及本次评测文本在脚本内做去重，训练和校准使用不同姓名；姓名和表达仍可能在项目历史中出现过。门控使用的例子少、校准阈值不构成风险保证；姓名结果本身来自程序登记的身份与地址。最终是否回答、时间选择、真实记忆内容、完整句子和崩溃恢复均未测试。本轮保存独立研究候选，不启用默认路径。

结果表明拆开两项判断可以在旧题中拦截多人误接，但代价是召回进一步下降，且新问法仍会误接。下一步需扩大并独立划分多人、推荐、否定和属性问题，改善姓名地址校准，再进行真实端到端验证；不能用离线组合代替实际调用结果。

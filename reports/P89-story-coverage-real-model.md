# P89：真实模型上的故事采样覆盖与恢复检查

独立入口 `scripts/train_conversation_coverage.py` 默认不启用记录；本次用 P34 父检查点、原个体和先前有限审核的 P28 故事源，启用文档边界及覆盖记录，进行两步工程诊断。使用的计划 `configs/p89-story-coverage-one-step.json` 最初为单步验证而命名；第一步完成后追加第二步用于恢复比较。两步均为故事预训练，未进行对话 SFT，也没有引入新语料。父检查点、原个体和旧运行不被覆盖。此前审核范围仅限有噪声的故事诊断，不代表事实质量或自由聊天能力。

分别执行先跑一步再恢复一步，以及从同一父检查点连续跑两步；模型张量、优化器、Python、CPU 和 CUDA 随机状态、批次摘要、目标计数、focus 游标和故事覆盖状态均逐项相等。检查点文件 SHA-256 不同，不能据此推断参数不同；差异中包含运行时间等元数据。分段检查均报告旧个体张量摘要不变，合成记忆探针 `[7,5,9,3]` 通过；它不证明自然语言个人记忆对齐。

两步共呈现 17,518 个故事目标，覆盖 88 个不同文档中的 17,518 个不同位置，记录到重复 0；这只描述该次短运行，不是整个数据池的覆盖率。首步为 8,506 位置、44 个文档。采样和统计不含焦点替换或其他来源；本次前两步未触发 focus 替换。启用或关闭记录的批次、参数及模拟焦点替换一致性另由合成 CPU 测试覆盖；尚未在真实 GPU 运行中比较统计开关两侧，也未验证真实焦点替换步骤。

连续两步的段内计时约 78.6 秒、峰值显存约 845 MB；恢复路线报告累计约 93.6 秒、最后分段峰值约 844 MB。计时包含监测但不涵盖所有文件校验，单次数据不应当成设备基准。运行材料、检查点与逐步评估只保存在 `runs/p89-story-coverage-one-step/` 和 `runs/p89-story-coverage-continuous/`；两步太短，不用于推断中文能力或改变聊天验收结论。

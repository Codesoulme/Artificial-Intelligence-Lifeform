# 联合训练记忆桥与冻结桥的同起点对照

## 设置

从上一轮平衡回放候选出发，两组都继续训练 768 步，使用相同初始化、训练样本、随机种子、旧值回放及评测问题。联合组除记忆读取器和语言适配器外，还以 `2e-6` 学习率更新共享记忆桥；对照组冻结该桥。训练后的两个候选独立保存，原个体和底座不变。

两组训练前的 84 条输出逐词元相同。训练后实际核查桥接权重：联合组相对起点的参数差 L2 范数约为 `0.0316`，冻结组为 `0`。联合组多训练了这部分参数，梯度裁剪涉及的参数集合也不同；两组按步数匹配，不是完全相同计算量，只有一个随机种子。

## 结果

| 留出人物、固定开发问法 | 联合桥 | 冻结桥 |
| --- | ---: | ---: |
| 单人状态：所选旧事实 | 6/6 | 6/6 |
| 单人状态：近期监督事实 | 4/4 | 4/4 |
| 单人状态：本轮留出事实 | 0/6 | 0/6 |
| 多人状态：所选旧事实 | 6/6 | 5/6 |
| 多人状态：近期监督事实 | 4/4 | 4/4 |
| 多人状态：本轮留出事实 | 0/6 | 0/6 |

近期监督事实的反事实配对两组均为 3/4 两边答对；剩余一对切换到了一个留出值。完整 84 条生成结果中有 83 条逐词元相同；唯一不同发生在一条多人旧事实问题：联合组回答目标水果，冻结组回答另一水果。样本过少，不能由这一条认定联合训练普遍优于冻结。

近期监督事实从起始候选的 3/4 改善到两组的 4/4，说明继续训练在这个受控集合中有用；因为冻结对照也达到同样结果，不能把改善单独归因于桥接权重更新。六种留出事实依旧全部答错，未解决开放词汇问题。

新进程重载联合候选，6 条旧值输出逐词元复现；训练人物与留出人物在四种近期监督值上各为 4/4，在额外检查的两种留出值上各为 0/2。三条关闭记忆路径的普通问题装载前后输出一致，范围不足以证明一般语言能力保持。受控记忆读出经共享码本核验，身份与地址由程序指定；没有检验自然写入、真实个体状态或开放聊天。结果属于已反复使用的小型开发集，且底座预训练覆盖未知，候选不部署。

## 研究与后续

[MEMORYLLM](https://arxiv.org/abs/2402.04624) 探索变换器潜空间中可更新的固定容量记忆；[M+](https://arxiv.org/abs/2502.00592) 在相关架构中研究长期记忆与共同训练的检索器。它们的结构、训练规模与本实验不同，本轮只是测试一个低成本桥接改动，没有复现两项工作。后续应研究更有表达力的读出表示和多样化重建任务，同时固定新的未见事实、无关问题和多人对照，而非仅延长当前水果训练。

联合训练 `scripts/deepseek_spora_joint_bridge_multifruit_pilot.py`，匹配对照 `scripts/deepseek_spora_frozen_bridge_matched_pilot.py`，新进程重载 `scripts/deepseek_spora_joint_bridge_reload_audit.py`。逐项结果位于 `runs/continuous-reader-joint-bridge-multifruit-pilot-20261113/`、`runs/continuous-reader-frozen-bridge-matched-pilot-20261113/` 和 `runs/deepseek-spora-joint-bridge-reload-audit-20261113/`。每组均有独立恢复文件；新桥的梯度参与和共享参数不重复加入优化器已用测试检查。

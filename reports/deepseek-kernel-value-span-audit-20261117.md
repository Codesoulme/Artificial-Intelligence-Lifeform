# 事实值边界与单位置读取退化

用留出人物“小赵”和两条人工事实（饮品为豆浆／咖啡），分别比较 [原注意力向量候选](deepseek-learned-kernel-probe-20261117.md) 和 [首词监督候选](deepseek-kernel-counterfactual-train-20261117.md)。两种写入方式分别把整句的 7 个词元，或由实验按 tokenizer 字符偏移明确指定的事实值 1 个词元，转成临时 key/value 状态；问题输入不包含事实值，不传事实前向的 KV 缓存。事实值对应的隐藏表示仍是在整句前文下计算，不能称作只看了一个孤立词。

两种候选、两种写入方法和两个事实共 8 条自由输出，**全部回答咖啡**。两种候选在单词元写入时，强制相同回答前缀后的两项 logits 也逐项相同；整句写入则随候选发生变化。豆浆状态下其首词排名在整句方式为 154／92，在单词元方式为 164／164；咖啡在两种条件均为第一。人工前缀分数不是自由生成概率评测，不能用排名变化替代答对。

## 发现的结构限制

当前正特征读取形式是 `qφ @ (kφ.T @ v) / (qφ @ sum(kφ))`。如果只写一个 key/value，分子与分母共享同一正标量，因此结果**恰好是该位置的 value**，与 q、k 映射无关（浮点误差除外）。已有合成测试核对输出等于 value，且映射参数的梯度近零。这解释了为何两份不同映射候选在单词元方式下的输出相同，也意味着仅训练这两个映射无法改变单位置读取值；本次没有训练 value 或输出映射。

多位置时该结构是正权重下各 value 的加权平均，读取不能单靠改变 q/k 权重产生这些 value 凸包之外的向量。当前单例并不能证明这是所有失败的唯一原因，也不能证明只加 value 映射就能正确回忆；仍需匹配对照和独立事实验证。

边界由实验给出且只留一个位置，**不是自动识别人物或事实的能力**；单位置状态也不能区分同内容的不同人物。本轮一个人、一种关系、一对已在项目中研究的饮品和固定问法，未评估自然写入、无关话题、未知拒答、多事实共存或持续保存。正式个体未修改。独立进程重新加载两份候选并核对来源摘要，但没有同输入逐项比较训练前后保存输出。

脚本 `scripts/deepseek_kernel_value_span_audit_20261117.py`，本机结果 `runs/deepseek-kernel-value-span-audit-20261117.json`；运行约 93 秒，PyTorch GPU 峰值约 3.33 GiB。5 项相关单元测试通过。下一步应在隔离候选中比较**可学习 value／输出映射**与保持原结构的匹配对照，训练身份与值的换值任务，并检验多词事实、未知与普通问题；不得将本次人工边界当成自然记忆成功。

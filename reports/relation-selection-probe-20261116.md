# 多关系问题选择探针

## 目的与方法

此前多关系生成实验由程序指定单一地址，不能证明语言模型能从多个关系中选择目标。本实验冻结现有 DeepSeek/SPORA 特征，提取问题的池化隐藏表示，训练独立线性四分类头：饮品、颜色、活动、拒绝。拒绝类包括否定、改写、推荐及查询事实属性等请求。没有读取记忆或修改正式路由。

数据为 112 条人工句子：训练 72 条，开发与测试各 20 条；三个集合在本实验内部使用不同人名和问法。训练 300 步，类别加权交叉熵，直接 argmax，未做拒绝概率校准。测试结果：

| 测试类别 | 正确数 |
| --- | ---: |
| 饮品 | 4/4 |
| 颜色 | 4/4 |
| 活动 | 4/4 |
| 拒绝 | 6/8 |

测试集中相同问法各配两个人名，不能视为独立表达；两个拒绝错误是同一“饮料味道”问法。开发集的两个拒绝错误是同一“饮品价格”问法。以上均误判为饮品查询。

## 额外压力样本

冻结并重载头部参数，再用新写的 18 条句子探查；未用这些句子调整训练：饮品 2/2、颜色 1/2、活动 2/2、拒绝 8/12。错误包括“中意的色调”误拒绝，“饮料温度”“饮料和颜色”误选饮品，“电影”与“活动时间”误选活动。每条仅一个人物和手工标签；这是探索性检查，不代表真实错误率。

## 判断与边界

主机特征在线性头下能区分本组简单关系，但存在属性、混合关系和未知关系的明显混淆；不能接入实际路由。关系判别无法确认人物是否存在、事实是否存在或请求是否获授权，更无法证明正确读出或生成。下一步应构造多事实共存的受控评测，把关系选择与身份、存在性及答案读取分别检验；拒绝条件需在新的独立数据上验证，不能依靠本组样本调阈值后宣布可靠。

源底座、个体与来源候选经摘要检查未变化。离线探针入口 `scripts/deepseek_spora_relation_selection_probe.py`；另一次进程重载头部并运行压力样本的入口 `scripts/deepseek_spora_relation_selection_stress.py`。结果保存在本机 `runs/deepseek-spora-relation-selection-probe-20261116/` 和 `runs/deepseek-spora-relation-selection-stress-20261116.json`；重载只证明该头部可在新进程使用，不是端到端个体恢复。

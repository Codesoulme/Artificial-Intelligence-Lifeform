# 省略追问的上一轮字段分类

沿用同一个继承判定、当前问题分类器和 0.60 读取阈值。继承前文时比较原双轮分类器、限制原分类器仅对上一轮词元取权重、独立训练的上一轮分类器，以及两种分类器有分歧时延后读取的方案。独立分类器使用 36 条既有省略追问的前文和 12 条时间与地点对照样例，训练文本未出现在评测前文中。新方案只改变字段分类，生成仍能读取同样的会话提示。

对话检索研究将历史中哪些内容要带到当前问题作为独立预测任务。本轮把这个思路用于字段选择，并分别统计读取覆盖率和错误放行率。相关论文的实验任务与本项目不同。 [Query Resolution for Conversational Search with Limited Supervision](https://arxiv.org/abs/2005.11723) · [Selective Classification for Deep Neural Networks](https://arxiv.org/abs/1705.08500)

| 评测集 | 原字段分类正确 | 独立分类正确 | 正确放行，原版 → 独立 | 错误放行，原版 → 独立 |
|---|---:|---:|---:|---:|
| 校准集 | 11/14 | 14/14 | 5 → 7 | 0 → 0 |
| 原留出集 | 17/20 | 18/20 | 10 → 10 | 1 → 0 |
| 6 对时间与地点题 | 8/12 | 11/12 | 2 → 5 | 1 → 0 |
| 双对象迁移题 | 8/10 | 9/10 | 4 → 5 | 1 → 0 |
| 新混合问法 | 11/12 | 10/12 | 4 → 4 | 0 → 0 |

限制原分类器的注意范围后，四组留出题的正确分类与放行计数和原版相同。要求两种分类器意见一致，在这四组题上去掉了原版的三次错误放行，正确放行次数与原版相同。独立分类器也去掉了这三次错误放行，并多正确放行四次。新混合问法中字段分类少对一条，正确和错误放行数相同。

在双对象聊天实测中，完整事实复现由 8/12 增至 10/12，新增的两个答案来自同一饮品追问的原值和更正值。两个回答都有“喜欢喝喝”的重复。日期追问从地点改判为日期，置信度约 0.58，最终请求澄清。地点追问仍被继承判定分入当前问题路径，进入普通生成。四个对照问题在两种模式下均未输出库内事实。

实验入口通过 `--inherited-router` 选择独立分类器，原模式继续作为默认。要准备分类器并启动入口，在仓库根目录依次运行：

```powershell
.venv/Scripts/python.exe scripts/deepseek_memory_inherited_turn.py
.venv/Scripts/python.exe scripts/deepseek_continuous_memory_chat.py --entity 26 --inherited-router --json
```

四种方案在 68 条对话上共生成 272 条路由判定，已核对每组计数、唯一性与产物 SHA-256。训练和路由评测约 78 秒，运行记录位于 `runs/deepseek-memory-inherited-turn/`。对象地址由入口参数指定。完备性结论仍受手写题量、固定对象及单轮历史限制。

## 重训继承判定

用 117 条样例重训是否承接前文的判定器。其中 24 条新增样例由 12 对省略追问和独立请求组成。对照组沿用末轮最末位置的隐藏状态，另一组加入末轮用户词元的平均表示。两者使用同一训练样例、优化方法和 20 条校准题，得到的继承阈值均为 0.75。原判定器沿用 0.50。三组共用上一轮字段分类器及 0.60 字段读取阈值。

| 留出评测 | 漏承接，原版 → 重训 | 正确放行，原版 → 重训 | 错误放行，原版 → 重训 |
|---|---:|---:|---:|
| 原留出集 | 0 → 0 | 10 → 10 | 0 → 0 |
| 时间与地点题 | 0 → 0 | 5 → 5 | 0 → 0 |
| 双对象迁移题 | 1 → 0 | 5 → 6 | 0 → 0 |
| 混合问法 | 1 → 0 | 4 → 5 | 0 → 0 |
| 8 对新问法 | 1 → 0 | 7 → 8 | 0 → 0 |

两个重训方案在 70 条留出题上的承接决策相同，都恢复了三条追问，没有增加误承接。实验入口采用末轮隐藏状态版本作为可选项。双对象端到端实测由 10/12 提升到 12/12，新增的是同一地点追问的两个版本。两个答案先复述问题再说出地点，已有饮品答案仍有“喝喝”的重复。四个对照问题均未输出库内事实。这里的 12/12 计完整事实复现，表达质量另计。

在已有上一轮分类器产物的基础上，可以训练并启动这组候选：

```powershell
.venv/Scripts/python.exe scripts/deepseek_memory_inheritance_gate.py
.venv/Scripts/python.exe scripts/deepseek_continuous_memory_chat.py --entity 26 --inherited-router --retrained-gate --json
```

核对了六组共 270 条路由判定、计划与检查点摘要，训练及路由评测约 72 秒。产物位于 `runs/deepseek-memory-inheritance-gate/`。本轮对象仍由入口参数指定，留出题仍为手写对话。

## 调整事实注入时机

逐词回放发现，完整饮品和地点句首的注入分数约为 0.70 和 0.77，低于原先的 0.80。模型继续生成后才触发，分别多出一个“喝”和一段重复提问。基于这两条已知失败选定 0.65，对照两种阈值。路由、句首适配器和矩阵保持一致。

| 回放组 | 完整事实，0.80 → 0.65 | 符合陈述句筛查，0.80 → 0.65 |
|---|---:|---:|
| 双对象回归题 | 12/12 → 12/12 | 8/12 → 12/12 |
| 新问法 | 10/12 → 10/12 | 10/12 → 10/12 |

陈述句筛查要求回答以预期事实收尾、句首接谓语、无重复结尾且未复述疑问句。两组共 60 个唯一生成组合，各版本均未输出其他已存事实。新问法中，两次澄清来自同一职业问题的两个记忆版本，字段选择正确但未达到读取阈值。测试仍是手写的短对话，筛查未涵盖指代和所有语病。

`--earlier-readout` 启用候选，默认保留 0.80。实际命令行验证了饮品追问从第 5 步提前到第 4 步注入。对照脚本 `scripts/deepseek_memory_timing_compare.py` 耗时约 106 秒，产物位于 `runs/deepseek-memory-timing-compare/`。

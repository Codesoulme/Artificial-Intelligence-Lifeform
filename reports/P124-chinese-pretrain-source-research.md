# P124 中文连续预训练语料来源调研

调查日期：2026-11-09。本文只读取一手数据卡、项目仓库说明、论文摘要以及本地 P52、P71、P77、P117、P121 证据；没有下载大数据正文，没有读取最终测试正文，没有训练，也没有修改其他文件。外部页面的规模和过滤描述是提供方声明或论文报告，不是本机重算结果；许可讨论不是法律意见。

## 结论

截至本次调查，没有发现同时满足“大规模、现代中文质量可验证、逐条权利清楚、隐私风险可接受、可直接用于本机训练”的公开整包。最值得先做小规模、训练侧受限核查的是 **FineWeb2 的 `cmn_Hani`**；最值得作为质量对照的是 **CCI3.0-HQ**；若优先考虑许可表达和可追溯性，可并行核查 **WanJuan 1.0 的文本子集**。**SkyPile-150B 不建议作为首个候选**，即使它的中文规模最大。

这些排序是“下一步审查价值”排序，不是训练批准：

1. **FineWeb2 `cmn_Hani`：优先级 A，先做小批审计。** 它有公开处理代码、字段级 URL/日期/语言/MinHash 簇信息，并在论文和数据卡中报告了中文 1.45B 从零训练对照；但 ODC-By 只约束数据集层，不能替代网页作者权利核验。
2. **CCI3.0-HQ：优先级 A-，作为质量基准候选。** 论文直接报告 0.5B 模型从零训练和与 SkyPile/WanJuanV1 的比较，过滤路径也更偏质量；但 Hugging Face 页面是 gated，数据卡元信息包含有害实验限制，当前没有确认完整许可条款和逐项来源权利。
3. **WanJuan 1.0 文本：优先级 B+，先核查具体子集协议。** 项目说明明确列出网页、百科、书籍、专利、教材和试题，声称进行了规则/模型清洗、多尺度去重和人工结合算法的价值评估；总许可声明为 CC BY 4.0，但特别写明部分子集适用其他协议。
4. **中文维基百科固定版本：优先级 B，作为可追溯百科补充。** CC BY-SA 3.0/GFDL 和页面 URL 提供较好的来源线索，但 P71/P77 已证明格式残留、事实时效、主题偏向、个人信息和旧材料重合仍需处理；它适合知识文体补充，不是现代连续语体的完整替代。
5. **中文教育网页候选和 ChineseWebText2.0-HighQuality：优先级 C，暂不扩大。** 数据卡和模型分数提供筛选线索，但 P52、P59 的本地抽查已看到隐私模式、商业宣传、名单、时效内容、危险建议、转载和残缺文本；许可覆盖范围也没有逐条厘清。
6. **SkyPile-150B：优先级 C-，仅在许可和分片可审计后考虑。** 规模和中文覆盖很强，但社区许可证、底层网页权利、个人信息以及公开过滤统计的可复核性都不如首选路径。

## 一手来源核查

### FineWeb2 中文

一手数据卡：[HuggingFaceFW/fineweb-2](https://huggingface.co/datasets/HuggingFaceFW/fineweb-2)。论文：[FineWeb2: One Pipeline to Scale Them All](https://arxiv.org/abs/2506.20920)。本次查看的数据集修订为 `af9c13333eb981300149d5ca60a8e9d659b276b9`，数据卡最后修改时间显示为 2025-10-27。

数据卡表格给出的 `cmn_Hani` 是 543,543,038,750 个 word-tokenizer words、636,058,984 篇文档、2.42 TB UTF-8 bytes 和 1.48 TB disk size。这里的 words 不是项目 tokenizer 的训练词元；不能直接与 SPORA 的目标词元相加。论文概述的是近 100 个 Common Crawl 抓取、超过 1,000 种语言、约 20 TB 和 50 亿文档的整体资源。

处理方面，FineWeb2 按语言做全局去重，每个重复簇只保留一篇，并在 `minhash_cluster_size` 中保存簇规模；数据卡还提供基于簇和过滤率的 rehydration 权重。其过滤大体沿用 FineWeb：质量过滤、Gopher repetition 等，并针对多语言实验调整了阈值；C4 过滤在该多语言设置中被移除，因为实验显示会损害表现。邮箱和 IP 做匿名化，另有 FTFY 编码修复和表格抽取残留修复。数据卡明确说明这些过滤不是针对每种语言单独设计的；中文入选不等于现代、连贯或事实可靠。

许可证是数据卡声明的 ODC-By 1.0，并同时受 Common Crawl Terms of Use 约束。它提供 URL、抓取日期和文件路径，利于逐站核查，但不等于每个底层网页作者都授予训练权利。P52 已在另一个 ChineseWebText 高质量网页子集发现手机号、邮箱、证件号、司法信息、商业宣传、危险建议、拼接和编码问题；P85 也提醒网页集合可能包含转载和个人信息。因此 FineWeb2 的优势是审计入口和可重现处理，风险是规模越大，集合级许可越不能替代逐站权利与隐私清理。

对小模型的相关证据比多数候选更直接：数据卡和论文使用 1.45B 参数模型、约 30B tokens，对包含中文在内的九种语言做数据集消融和任务评价。这说明从随机初始化进行有限规模预训练是可行的研究路径，但它没有证明 SPORA 的词表、优化器、数据比例或较小模型都会得到同样结果；评估指标也不是故事、对话或隐私质量认证。

### WanJuan 1.0

一手仓库：[opendatalab/WanJuan1.0](https://github.com/opendatalab/WanJuan1.0)。论文：[WanJuan: A Comprehensive Multimodal Dataset for Advancing English and Chinese Large Models](https://arxiv.org/abs/2308.10755)。

仓库 README 声称整个多模态语料超过 2 TB；文本部分超过 5 亿文档、超过 1 TB，来源包括网页、百科、书籍、专利、教材和考试题，统一为 JSONL。它描述语言筛选、文本抽取、格式标准化、规则和模型过滤、多尺度去重、质量评估，以及算法与人工评估结合的价值对齐。文本内容类型跨度很大，不能把书籍、教材、百科和网页行数当作同质连续语料。

README 的整体许可证声明为 CC BY 4.0，要求署名、许可链接和修改说明；同时特别提醒部分子集可能适用其他协议，使用具体子集前必须查看其元数据或协议。这个限定是关键：书籍、专利、教材、试题和网页的底层权利不能由总 README 自动解决。数据卡示例还显示翻译文学、历史材料和来源注释可能进入同一文本池，需逐文档追溯。

论文说明它被用于 InternLM 等大模型体系，但没有提供与 SPORA 同配置的小模型、同词表、同训练预算的独立证据。它适合作为一手来源账本和小批质量对照，不适合在未拆分子集协议、来源、隐私和重复族前直接接入。

### SkyPile-150B

一手数据卡：[Skywork/SkyPile-150B](https://huggingface.co/datasets/Skywork/SkyPile-150B)。相关论文：[Skywork: A More Open Bilingual Foundation Model](https://arxiv.org/abs/2310.19341)。

数据卡声称公开部分约 2.33 亿个独立网页、平均每页超过 1,000 个中文字、约 150B tokens、620 GB plain text。它描述了规则清洗、去重、敏感信息过滤、URL 筛选，以及 fastText 和 BERT 的低质量过滤；安全部分又称使用超过 200 万条规则和 BERT-base 检查敏感数据。数据卡同时承认网页可能含邮箱、电话、IP，且过滤不能消除有害或偏见内容。

许可证不是 Apache 或 CC，而是 Skywork Community License；README 称支持商业使用，但若使用 Skywork 模型或其衍生物还要遵守该社区许可证和 Apache 2.0。必须把“数据集可获取”“数据集条款允许的用途”“底层网页作者权利”分开核对。公开卡没有给出足够的逐站授权账本、隐私残留率、中文质量误报/漏报或跨公开评测隔离证明。

SkyPile 对小模型的价值主要是规模和中文覆盖，不能直接作为质量依据。若以后核查，应先做固定版本的小分片、来源域分层和 PII/格式盲样审查；在此之前不建议为本机下载或规划全量。

### CCI3.0-HQ

一手论文：[CCI3.0-HQ](https://arxiv.org/abs/2410.18505)。数据集：[BAAI/CCI3-HQ](https://huggingface.co/datasets/BAAI/CCI3-HQ)。论文称它是 CCI3.0 的 500 GB 高质量子集，使用两阶段混合过滤，并训练 0.5B 参数模型、100B tokens、十项 benchmark 做零样本比较；报告中比较了 CCI3.0、SkyPile 和 WanjuanV1。

这使它成为本次候选中最贴近“随机权重小模型能否从连续中文学习”的公开证据之一。但论文结果是提供方的数据配方、模型、分词器、训练预算和评测组合，不能替代本机复现。质量过滤使用模型驱动部分，公开摘要强调从 Qwen2-72B-Instruct 能力中蒸馏出网页质量分类器；这会带来模型偏差、训练数据污染和许可边界问题，尤其不能把质量分类分数理解为事实或版权证明。

Hugging Face 元数据显示该数据集 gated，含 `score` 字段，并有“不得用于造成伤害的人体实验”等额外同意提示；本次没有下载或申请访问。当前未在本地确认完整数据集许可证、底层网页权利、隐私清理细节和与 SPORA 既有材料的重合。因此它是质量对照优先项，不是立即可用训练源。

## 中文教育和百科来源

### ChineseWebText2.0-HighQuality 与 FineWeb-Edu-Chinese

P52 记录的 `Morton-Li/ChineseWebText2.0-HighQuality` 固定版本声明 Apache-2.0，数据卡描述 `quality_score >= 0.9`、低 toxicity 分数和领域标签，但 P52 只检查了一个 100,000 行分片，发现 336 条手机号样式、118 条邮箱样式、122 条身份证样式和 4,661 条司法词命中；抽样还出现商业宣传、活动名单、时效新闻、危险建议、残缺和无关拼接。规则命中不是隐私确证，未命中也不是安全证明。Apache 标签同样不能自动授予底层网页作者权利。

P59 检查的 `opencsg/Fineweb-Edu-Chinese-V2.1` 固定版本声明 Apache-2.0，但数据卡另提 OpenCSG Community License 及商业使用联系要求；权利范围未厘清。30 条抽查主要是专业长文或转载，出现医疗、法律、时效事实、抽取残缺和语义不通。它可以作为教育价值筛选研究对象，当前不应当作清洁基础语料。

### 中文维基百科和其他教育/百科材料

P71 的 Wikimedia 中文 Wikipedia 20231101 数据卡声明 CC BY-SA 3.0 和 GFDL，提供页面 URL、标题和正文，来源追溯明显优于无 URL 的网页混合物。但 P71/P72 的两个 40 条样本仍有目录、引用、图表/公式缺失、繁简混排、消歧义列表和时效性问题。P77 在训练侧首段上进一步发现 8,150 条中的大量标题不锚定、列表残留、疑似承接和敏感线索；机械分层不等于质量通过，页面许可也不消除个人信息或第三方引文问题。

P69 的百科候选抽查显示，书面百科能提供连续知识文本，却不等于现代对话，且常含参考书目、图像说明、专业断言和时效信息。P84 的中文维基教科书候选约 246.7 万字符，规模太小，且 CC BY-SA/GFDL 的页面与第三方教材内容仍需拆分。它们适合做小比例知识/书面文体补充，不适合单独承担中文基础预训练。

## 与本项目证据的合并判断

P117 说明本项目现有 MiniMind 对话训练侧清单有 77,437 条记录、约 17.67M 助手目标，但混合上游逐条权利不清，质量和近重复仍未完成；它不能作为外部大语料的质量基准。P121 对 P120 故事候选 200 条的四模型盲审得到 clean 81、minor 87、major 32，至少 119 条有缺陷标签。这证明当前故事候选不能直接用来承担中文连续预训练，也说明自动分数或简单来源标签不足以替代分层内容复核。

P52 和 P71 的共同信号是：来源字段与自动分数提高了可追溯性，但网页/百科集合仍会保留隐私、格式、时效、转载和专业错误。P77 还证明首段规则会有选择偏差，不能把“没有触发规则”解释为可训练。FineWeb2 和 CCI3.0-HQ 的论文小模型实验提高了“从随机权重学习连续文本”这一方向的可行性证据，但没有消除本项目自身的权利、重复、隐私和中文语体问题。

## 本机候选工作包和最低门槛

### 第一阶段：不下载大数据的元数据预审

对每个候选固定版本、数据卡、论文、许可证全文、下载清单和处理代码做摘要登记，至少保存：来源仓库和修订、数据卡修订、许可证原文 URL、子集名、文件摘要、字段、URL/时间/来源字段、是否 gated、是否允许派生和发布、删除/投诉通道。没有这些字段的候选保持 `unresolved`，不进入正文采样。

### 第二阶段：小分片、分层、低资源审计

每个候选先取不超过 1,000 条文档或约 1–5M 字符，不下载整包；按来源域、语言/脚本、长度、内容类别、时间、质量分位和 PII 规则分层。审计只保存哈希、来源域摘要、行号、规则计数和判断，不把正文写入仓库。对 FineWeb2 优先利用 URL、date、language_score、minhash_cluster_size；对 WanJuan 先按文本子集和协议分开；对 Wikipedia 按页面版本和历史；对教育集合按医学/法律/时效/转载与教材来源分层。

### 第三阶段：最低放行门槛

在任何本机训练侧使用前，候选必须同时满足：

- **权利**：数据卡声明、子集协议和计划用途一致；底层来源存在可追溯证据。ODC-By、CC BY、CC BY-SA、Apache 或社区许可证不能互相替代；不能用集合标签覆盖书籍、网页转载、专利、试题和第三方引文。
- **完整性**：固定版本和文件摘要可复现；随机抽取记录可由来源行/URL追溯；格式、编码、段落边界和文档结束标志通过检查。
- **隐私**：对邮箱、电话、证件、地址、姓名组合、医疗/司法个人信息做规则筛查，并对命中和未命中层分别盲审。任何明确个人敏感信息或无法安全判断的记录隔离；不得以零规则命中宣称匿名。
- **重复和隔离**：精确、字符 5-gram/MinHash 近重复按文档族处理；跨来源与 P52/P71/P77/P117 既有训练侧按哈希或受控比对检查；与最终评测的检查由独立保管方只返回汇总或阻断，本机不打开最终正文。
- **内容质量**：每个主要来源域和长度层至少抽 50 条完整文档，至少两次独立模型复核；质量标签包含缺损、拼接、事实/时效风险、模板、专业风险、语言不自然和不确定。重大安全/隐私问题必须为 0；对普通质量问题要报告分层分母，不能只报总平均。
- **用途适配**：连续预训练候选必须以完整文档为单位保留，而不是把指令-回答连接误当文章；教育和百科作为知识文体单列，故事和对话单列，不混成“通用高质量中文”。

以上是“进入受限开发侧实验”的最低门槛，不是发布或商业使用批准。若主要来源域的复核无法达到 50 条完整样本、独立复核无法覆盖、或权利链仍含重大空白，则保持待审，不用扩大下载来替代证据。

## 可执行优先顺序

1. **先做 FineWeb2 `cmn_Hani` 的 1–5M 字符审计**：只取少量固定分片或官方可读样本，按域和 `minhash_cluster_size` 分层；同时保留 URL、日期和语言分数。重点验证中文语体、转载/百科/广告比例、PII 命中、与 P52/P71/P117 的精确和近重复。若权利仍只能停在 ODC-By + Common Crawl 层，结果只能作为研究候选，不可直接训练。
2. **并行申请/核查 CCI3.0-HQ 的卡片、许可证和访问条款**：不先下载。优先确认是否允许本地非商业研究、派生筛选、内部报告和后续模型训练，记录 gated 同意文本；若不能取得底层权利或完整处理说明，降级为论文基准，不使用数据。
3. **核查 WanJuan 1.0 的文本子集协议**：按网页、百科、书籍、专利、教材、试题拆分，先只选协议明确、能保留来源字段的子集。对教育/百科子集复用 P77 的标题/段落/个人信息/格式审计，不能把整体 CC BY 4.0 当作所有子集的通行证。
4. **构建固定版本中文 Wikipedia 小子集**：只保留页面版本、作者/历史、许可、引用和页面 ID 全部可追踪的条目；把百科当作低比例知识补充。先解决 P71/P77 的残留和重合，再算有效字符/目标词元。
5. **暂缓 SkyPile、ChineseWebText2.0-HQ 和 FineWeb-Edu-Chinese 的整包获取**：它们可以继续作为来源发现或质量对照，但 P52/P59 已给出足够理由要求更细的权利、隐私和内容复核。不要以 150B、500GB 或高质量标签本身推进训练。

## 对随机权重小模型的实际含义

公开证据支持“经过清洗的连续中文数据可以用于从零初始化模型的可行性研究”：FineWeb2 报告 1.45B 模型的 30B-token 跨语言消融，CCI3.0-HQ 报告 0.5B 模型的 100B-token 训练。它们不支持“任意大网页集都适合小模型”，也不支持“清洗分数等于事实质量”。对 SPORA，先把目标定义为数据可用性诊断：比较固定数据预算下的字符/目标词元有效率、重复曝光、验证损失、编码和结束行为、书面知识文体与对话/故事开发诊断；不要把一次小模型结果倒推授权或整体质量。

当前不建议启动训练。达到最低门槛后，才考虑在不碰最终评测的前提下，为每个候选建立独立训练侧和开发侧族划分，并用相同随机种子、模型规模、词表、目标预算和早停规则做小规模对照。P121 的故事缺陷结果、P117 的对话权利/重复限制和 P52/P71/P77 的网页/百科审计应继续作为阻断条件，而不是被新来源的总规模覆盖。

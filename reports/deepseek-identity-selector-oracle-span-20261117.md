# 人工姓名边界的神经选择对照

与 [句末向量方案](deepseek-identity-selector-probe-20261117.md) 使用相同姓名、句式、候选采样、网络、随机种子和训练步骤；改变输入表示：实验人工给出记录和问题中姓名的字符边界，验证 tokenizer 的词元边界完整覆盖姓名，再对这些位置的冻结 DeepSeek 最后一层隐藏向量取平均。普通问题没有人物边界，仍使用句末向量。这是人工边界上限诊断，**不是模型自动找出姓名**；该表示仍包含其前文的上下文影响。

| 同一开发集合 | 句末向量 | 人工姓名片段 |
| --- | ---: | ---: |
| 留出姓名已知查询正确 | 5/24 | 10/24 |
| 留出姓名已知查询误拒 | 17/24 | 10/24 |
| 留出姓名已知查询错选其他人 | 2/24 | 4/24 |
| 留出姓名未知查询误选记录 | 3/24 | 6/24 |
| 四组近名、各两问，误选记录 | 2/8 | 4/8 |

训练人物上，已知查询正确由 23/48 增至 31/48，但未知查询误选由 16/48 增至 24/48。近名中“阿宁宁”两种问法均选了“阿宁”；“老马力”一次选了“老马”；“小王子”一次选了另一个不相干的人。普通问题 3/3 选择无匹配，但普通问题使用句末表示，与人工姓名片段输入并不匹配，不能推广到自然查询。

已知正确率增加同时误关联也增加，不能只看一项将其判为安全改善。两组使用一个种子和极少人工姓名；近名是先前开发阶段观察后加入，结果不是独立盲测。记录中的姓名及问题边界均由程序提供，未处理别名、同名、指代、多人的自然句子、自动抽取、事实读取或模型生成；无匹配选择也不能保证底座不猜答案。

本轮约 103 秒，PyTorch GPU 峰值约 3.32 GiB；3 项姓名片段边界和选择器基础测试通过，但没有覆盖实际自然语句的定位器。来源底座散列前后相同，正式个体未修改；候选未做独立推理重载或部署。入口 `scripts/deepseek_identity_selector_oracle_span_20261117.py`，结果 `runs/deepseek-identity-selector-oracle-span-20261117/`，原先句末版本结果保留在 `runs/deepseek-identity-selector-near-name-probe-20261117/`。

下一步需要在冻结数据上分析分数分布和错读／误拒权衡，并引入可靠的主体边界与多主体上下文；任何阈值都必须用独立留出集验证，不能靠这组开发题挑选后声称安全。

# 两人状态混合的成对训练

沿用 [完整回答候选实验](deepseek-kernel-full-answer-train-20261117.md) 的底座、起点、两名训练人物、四种训练饮品、损失和 128 步预算；每步将目标人物与另一训练人物的两份独立短句 key/value 拼成一个状态。成对换值时只更改目标人物饮品，另一人物及其饮品保持不变；另一饮品从不同于这两个目标值的训练值中选择。两条事实分别编码，位置都从零开始；这不是自然连续对话或正式个体写入。

在每步随机改变两段拼接顺序。需要更正的是，当前读取把正特征的 key/value 外积与特征和分别相加，**数学上对这种重排本就不敏感**（浮点误差除外）；随机排序本身不能证明模型学会利用人物身份。训练没有改变这个聚合结构。

| 留出人物的六种状态、加同一个训练人物干扰 | 训练前 | 训练后 |
| --- | ---: | ---: |
| 人工回答前缀下，目标首词排名第一 | 1/6 | 1/6 |

训练后自由生成中，该留出人物的六种目标饮品**全部回答咖啡**，即使混入的另一人物饮品不同；没有任何一组成对换值两侧都正确。强制前缀下，目标豆浆首词排名从 143 提升至 3，但未成为首位；这不是自由回答成功。留出人物及两种留出饮品是相对于本轮监督划分，底座和早期实验可能见过相关词语。

这是一种训练尝试，不是与单人训练的完全匹配因果比较：本轮输入含另一条事实且进行了顺序随机化，原有单人候选训练不含相同干扰。留出人物只有一名，干扰人物和饮品选择也有限；没有独立进程重载、未知人物拒答、自动写入、真实持续状态或普通聊天回归。不能由此证明多人记忆架构不可行，但不能将候选用于正式个体。

训练约 191 秒、PyTorch GPU 峰值约 3.53 GiB；7 项相关损失与拼接辅助测试通过，真实模型多人钩子及训练过程没有自动化测试。底座和来源候选散列前后相同。入口 `scripts/deepseek_kernel_multi_entity_train_20261117.py`，逐项结果与隔离候选在 `runs/deepseek-kernel-multi-entity-train-20261117/`。

下一步应直接评估不同人物的 query 对合并状态贡献是否能区分，并研究保留人物与关系边界的分离式神经状态或可学习寻址；同时在未知主体、近名和独立值上设置拒答与错读对照。不能依靠当前顺序随机化或固定题目分数宣称已解决身份绑定。

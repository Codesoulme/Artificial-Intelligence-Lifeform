# Qwen 用户跨度约束的自然中文记忆寻址

日期：2026-11-21

## 背景

上一轮完整 token 注意力头的最高权重在 36 条留出问法中全部落到 chat template 的固定系统 token `You`。把输入直接裁成用户内容后，地址正确率反而从 `29/36` 降到 `21/36`，说明 Qwen 的对话上下文状态也被一并丢失。

## 本轮结构

本轮保留完整 chat template 的最终层隐藏序列，用完整序列计算最后有效 token 和全局平均；注意力分数只允许落在 tokenizer 精确定位出的用户消息 token 区间。这样把“查询内容在哪里”和“对话状态如何解释”分开处理。

语言模型、孢子个体、记忆矩阵、数字读取适配器和内部意图门均冻结。候选头只在 48 条训练问法上训练，36 条不同自然问法留出；候选没有接入正式运行入口。

## 结果

| 指标 | 原整体头 | 全序列 token 头 | 仅用户内容头 | 用户跨度约束 + 完整上下文 |
|---|---:|---:|---:|---:|
| 训练地址正确 | 48/48 | 48/48 | 48/48 | 48/48 |
| 留出地址正确 | 29/36 | 30/36 | 21/36 | **34/36** |
| 留出数值回答正确 | 27/36 | 28/36 | 18/36 | **30/36** |
| 记忆门开启 | 36/36 | 36/36 | 36/36 | 36/36 |

运行约 `63.2 s`，峰值显存约 `1.05 GiB`。候选产物位于 `runs/qwen-natural-memory-context-address-v1-20261121/`。

## 诊断

注意力最高位置已经集中到用户消息里的对象编号附近，说明上一轮的固定系统 token 捷径被去除，同时 Qwen 的完整上下文信息仍可用于输出。该设计显著改善了地址绑定，但还没有达到发布门槛。

剩余问题分开表现：

- 地址仍有 2/36 错误，主要出现在“编号 1／11 保存的数值吗”这类相近数字和特定问法组合；
- 有 4 条地址正确的问题仍未得到严格数值答案，出现重复数字、额外标点或不完整句子；
- 当前地址集合、数字值和问法仍是有限人工合成任务，不能外推到姓名、偏好、来源、时间或开放事实；
- 训练问法仍按模板划分，尚未完成按人物、句式和事实三重隔离的独立评测。

## 判定与后续

本轮通过“候选研究信号”门槛，但未通过正式接入门槛。用户跨度约束应保留为后续地址路由的结构组件；当前候选权重不覆盖正式个体。

下一轮优先处理地址和读出的解耦：用独立留出问法验证查询类型、对象跨度和未知事实拒答，再对数字值读取增加明确的停止和输出一致性约束。只有地址、数值、拒答和重载结果同时稳定，才允许接入本地交流入口。

# 自然句姓名识别与字段更正的隔离回放

上一轮直接提供完整姓名和字符边界。这次重载同一中文字段地址头，把四层姓名标注器的预测与个体中已登记的姓名指纹相交，再用匹配片段生成字段地址。每组四人、每人四个字段。初始值预先登记，更新值由题目提供，自动判断的是更正对象和字段。每人更正一次，随后查询全部字段。所有更改发生在固定长度的临时张量中。[字段地址](spora-entity-field-address-20261124.md) · [姓名标注器](registered-name-span-audit-20261123.md)

从同一组原句另造各 80 条负例。只把主语改成下一组未登记的人、原姓名后多一字的近名，或两个已登记姓名。负例仅尝试定位，记录若放行会写入的槽位。查询结果要求选择正确槽位并读回完整词元。

| 条件 | 正确写入 / 误写 / 跳过 | 更正值读对 | 未改值读对 | 未登记 / 近名 / 双人负例误放行 |
|---|---:|---:|---:|---:|
| 人工确认完整姓名 | 19 / 1 / 0 | 18/20 | 54/60 | 未测 |
| 唯一已登记指纹 | 19 / 1 / 0 | 18/20 | 54/60 | 0 / 80 / 0 |
| 标注器只识别出一个人名，且与指纹同范围 | 15 / 0 / 5 | 14/20 | 49/60 | 0 / 13 / 0 |
| 标注器所识别人名中，只有一个与指纹同范围 | 19 / 1 / 0 | 17/20 | 48/60 | 0 / 13 / 0 |

要求唯一人名时，漏掉了全部五条更换对接人的请求。句子里同时有记忆对象和新的对接人。允许第二个未登记人名能恢复这五条请求，但又出现将对接人写入地点槽的问题。两种标注策略都有 13 条近名被截短后放行。近名负例使用相同后缀，比例只能描述这批构造题。

人工确认对照重现上一轮的更正写入与读回，未改值由 55/60 变为 54/60。本脚本改为分别处理初始记录与混合了负例的自然句，并逐条计算候选地址。后续比较使用表内的同批人工对照。地址头、模型输入权重和个体状态的摘要在回放前后一致。两次独立进程运行得到完全相同的逐题 JSON。字段地址与姓名指纹的 10 项单元测试通过。

自然写入候选暂不接到正式个体。后续训练可把对象、充当字段值的人名和完整的库外长名同时标记，再用独立句式验证能否减少截短误写和联系人漏写。真实自由对话中的写入意图、值抽取、重启和生成仍需整体验证。

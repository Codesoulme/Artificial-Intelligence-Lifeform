# 路由探针的问法扩展对照

## 方法

保留上一轮基于冻结底座最后位置向量的三分类探针作为对照；新探针使用相同结构、类别加权与训练轮数，在原有 78 条训练问题之外，为每个人物与关系组合增加三种问法，共 183 条。训练与测试问题按文本去重，旧留出问题和本轮新问题均未加入探针训练。

先比较上一轮的 100 条开发问题；另构造 23 条新句式问题：七条已知事实、四名未参加本轮训练的新人物各三种关系，以及四条已知人物的未知关系。对这些新问题，冻结底座和两个保存的记忆候选各自实际生成回答，再按探针选择的路径比较输出。两个候选的参数、输出分工及已有开发问题此前已经观察过，因此这不是密封验收，也没有实现正式运行时路由。

## 结果

| 检查 | 原探针 | 扩展问法探针 |
| --- | ---: | ---: |
| 旧开发集：已知事实留出问法严格答对 | 10/14 | 11/14 |
| 旧开发集：未知人物及未知关系严格答不知道 | 34/56 | 41/56 |
| 旧开发集：普通留出问题选回底座 | 8/8 | 8/8 |
| 新句式：已知事实严格答对 | 3/7 | 4/7 |
| 新句式：未知人物严格答不知道 | 8/12 | 8/12 |
| 新句式：已知人物未知关系严格答不知道 | 2/4 | 4/4 |

扩展探针对 183 条训练问题全部分类正确，但未知问题的路径分类在旧开发集为 13/56，低于原探针的 16/56。分类选错时，有时另一路仍碰巧生成正确短答，因此路径分类和最终回答分数不同。

直接使用原样本候选时，23 条新问题分别为已知事实 6/7、未知人物 12/12、未知关系 4/4；扩展探针组合后为 4/7、8/12、4/4。新人物中四条未严格匹配的回答均来自底座的较长无法回答或建议联网，并非直接给出其他人的值；严格匹配低于直接候选不能单独证明这四条都是事实幻觉。已知事实的三条失败中，一条是所选记忆候选本身拒答，另外两条被错误送回底座。

## 判断与限制

增加问法改善了部分已见开发问题，却没有在这组新句式上超过直接使用候选。它也没有验证可扩展的个人事实识别，因此不能用于正式个体。普通留出问题选回底座仅意味着复用底座输出，不代表回答正确或完整。

新句式、四个人物及标签是手工合成的小样本；不能保证姓名、词语或类似表达未出现在底座预训练或项目更早开发中。每条关系只有一种新句式，样本之间并不独立；训练样本数量增加而计算预算未严格匹配。严格短答会把其他合理拒答计作失败，生成最多 24 词元。不存在自然观察写入、长时间记忆、多轮聊天或新进程运行时路由的验证。

底座摘要在试验前后核对一致；两份原候选摘要在开始前核对，试验未写入候选文件。探针仅存于隔离研究目录。本机运行约 136 秒，CUDA 峰值分配约 3.57 GB。代码及设计检查分别为 `scripts/deepseek_spora_router_paraphrase_audit.py`、`tests/test_router_paraphrase_design.py`；新问题的三路径回答及全部选择保存在 `runs/deepseek-spora-router-paraphrase-audit-20261116/result.json`。

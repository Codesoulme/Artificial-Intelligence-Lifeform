# 目前循环版的中文对话对照

前次三至五轮对照使用较早的孢子检查点，不能衡量本机聊天入口采用的第 19、22 层循环替换。此轮固定上一轮的六道题，对比原版 DeepSeek、替换前的孢子父检查点、以及在同一父检查点上安装两层循环权重后的候选。AFVE-Bench 把新要求、废弃要求及成品可用性分开判分。Hy-MultiTurn 划分对象定位、转题干扰和条件整合；*Lost with a Map* 将有效状态的信息、值的解析和在回答中执行分开。 [前次中文对照](spora-fresh-dialogue-20261125.md) · [AFVE-Bench](https://arxiv.org/abs/2611.10541) · [Hy-MultiTurn](https://arxiv.org/abs/2607.29196) · [Lost with a Map](https://arxiv.org/abs/2609.33883)

## 设置

三组均在本机用同一分词器、直接作答、贪心解码和 CUDA FP16。循环版与本机入口使用同一父检查点及两份替换权重。实验绕过入口的记忆查阅分流，普通对话保留全部历史和模型自己的旧回复，以便和前次对照同条件复跑。末轮前每轮给 96 词元，末轮和给定现行要求的单轮对照各给 224 词元。上限 1024 位置，检查每道题都保留所有前文及预定回复预算。历史只包含该题对话，个体档案在本轮保持冻结。

## 结果

| 指标 | 原版 DeepSeek | 孢子父检查点 | 两层循环版 |
| --- | ---: | ---: | ---: |
| 分轮末答可直接使用 | 0/6 | 0/6 | 0/6 |
| 人工整理的现行要求，可直接使用 | 0/6 | 2/6 | 2/6 |
| 分轮末答正常结束 | 6/6 | 6/6 | 6/6 |
| 分轮全程正常结束 | 23/24 | 24/24 | 24/24 |
| 分轮末答生成耗时中位数 | 4.00 秒 | 1.07 秒 | 1.04 秒 |

| 场景 | 孢子父检查点末答 | 两层循环版末答 |
| --- | --- | --- |
| 相馆取件 | 保留时间地点，漏掉取一张 | 未给具体时间、地点或数量 |
| 缺失的送达时间 | 无依据断言三点前收到 | 同父版 |
| 小组分工 | 只给最新集合时间和地点 | 同样漏掉分工 |
| 从植物转题 | 解释为冰块融成小冰晶 | 解释为杯内冰融化产生杯外水珠 |
| 复核后的文件交接 | 给出 PDF 和时间，句子结尾缺宾语 | 提到 PDF，丢掉下午并增加等待 |
| 雨天集合 | 地点正确，缺日期时间并恢复地图 | 地点正确，缺日期时间，同时要求准备地图及只带笔 |

两组孢子在单轮控制里都完成取件及小组分工。入口当前可用的两处循环替换会改变生成。两组在 24 个轮次中只有 6 轮回复逐字相同，末轮只在快递题相同。两个末轮会话可能含有不同的模型旧回复，因此逐轮结果包含回复差异沿对话传播的效果。单轮使用相同输入时，六条里五条回复逐字相同，差异出现在 PDF 交接，两个回答都漏掉条件。三组末答分别最多用 87、49、23 个词元，均在上限前结束。孢子末答更短，耗时差异不能用于比较单词元速度。

原版 DeepSeek 六条末答与前次存档逐字一致。底座本身在这批开放对话题上已有明显困难，两层循环替换也改变了对话中保留的具体细节。本轮使用现有权重，由同一审核者按预先定义的成品标准检查末答。运行约 240 秒，CUDA 张量峰值 3.38 GiB。逐轮输出、生成预算及权重摘要位于 `runs/spora-recurrent-chinese-v1/result.json`。

## 记忆查阅入口

在 Windows 聊天入口分别启动默认版和两层循环版。每个入口创建独立测试档案，通过 `/记` 登记八份新旧记录，然后退出并用相同档案重启。六个场景分别提供明确查阅、自然问法以及翻译、润色或取消查阅的对照。每道题前清空对话，记录实际读出的编号，并检查回答中出现了哪些登记值。测试涵盖旧饮品、改过的见面地点、相似姓名、用品和首版书目。引用实际读取编号可以区分答复走偏与未经请求读取，这是 *The Right Memory in the Wrong Context* 提出的评估思路之一。 [读取许可验证研究](https://arxiv.org/abs/2610.07309)

| 指标 | 默认入口 | 循环入口 |
| --- | ---: | ---: |
| 明确查阅读对编号和数值 | 6/6 | 6/6 |
| 自然问法读对编号和数值 | 0/6 | 0/6 |
| 自然问法发起澄清 | 0/6 | 0/6 |
| 无需查阅，零读取且未显示已登记值 | 6/6 | 6/6 |

所有自然问法均进入普通聊天。例如「陶依萍最近改喝什么了？我买前想确认一下」在默认入口收到联网建议，在循环入口收到「先不问，先按计划。」。非查阅对照只按实际读取和登记值披露判分。默认入口收到润色请求时自行编造了饮料品牌，循环入口收到照抄请求时猜了书名。两份档案都通过 SQLite 完整性检查，重启回放前后各自的摘要一致。默认版写入和重启回放分别约 32、47 秒，循环版约 52、59 秒，均含加载。另通过 10 项循环注意力及 59 项版次单元测试。逐题结果在 `runs/spora-natural-lookup-cli-v1/result.json`。

## 下一轮诊断

自然输入需要学到查阅许可、人物、事项及时间关系。11 月的 TransMem 显式表示更正和继承，能用已定位事实进一步找前后版本。HabitusMem 以当前请求判断历史偏好是否适用，评估表明这种条件化是主要增益来源。孢子已有版次张量和明确读取入口，可先固定这两者，用同人同事项的配对句学习输出查询动作及目标关系。单独评分是否读取、是否追问、地址是否正确，以及旧版或现行版是否正确。先引入给定正确地址的生成对照，再按失败集中处决定训练坐标头还是调整读出。六组本机新题保留为独立回归。 [TransMem](https://arxiv.org/abs/2611.10683) · [HabitusMem](https://arxiv.org/abs/2611.25855)

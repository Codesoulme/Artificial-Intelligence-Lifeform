# Incremental individual state bound to structural layers

The v3 integrated checkpoint includes replacement tensors and was about 233 MiB in the real probe. Rewriting that file on every memory update is costly. `IntegratedDurableRuntime` now pairs an unchanged v3 structural bootstrap with the existing transactional `TensorStore` for the evolving neural individual. The store records the bootstrap and base fingerprints; on reopen, the bootstrap content hash, checkpoint integrity, model configuration, address basis and declared binding variant are checked before the runtime is returned. The frozen DeepSeek base, structural bootstrap and state database remain separate files and are all required.

The runtime snapshots parameter identities/version counters and checks the bootstrap's file metadata during use. Ordinary in-place decoder changes or a changed bootstrap prevent a commit. These checks are not a security or tamper-proof boundary: callers must load the declared base honestly, `.data` mutations may evade tensor version tracking, and a file can be altered without a detectable stat change. The bootstrap's full content hash is verified on reopen. The store supports a single writer with revision-conflict detection; it is not a distributed or multi-user identity system.

In the real-model probe, two direct observations on one new key each staged 205,200 bytes of changed tensor payload across eight tensors. The first took 3.16 seconds and the second 0.24 seconds in this run. A separate full v3 save wrote a 244,114,744-byte checkpoint and took 49.23 seconds. These are single measurements under uncontrolled hardware load. Tensor payload counts are logical data, not physical disk writes: the SQLite file and WAL measured 4,546,560 and 4,589,712 bytes before close, and the database was 4,558,848 bytes after close. The initial load and store creation took 36.77 seconds, excluding initial base loading.

A fresh process reopened the database and bootstrap; cursor, state digest and generated token sequences matched before/after, and the two explicitly addressed current and past answers were correct. The previous attempt committed both synthetic writes but stopped because the benchmark called a nonexistent helper; it remains in its own directory. The corrected isolated run and exact metrics are in `runs/deepseek-spora-integrated-durable-probe-v2-20261111/result.json`.

Eighty-six targeted tests passed. Small-model process-termination tests exited the writer after its first staged tensor and after commit, then reopened the database: the former recovered the prior state, the latter the committed state. Other checks cover rejected stale writers, bootstrap mismatch, decoder mutation, failed-save state publication and independent reload. This is not a power-loss or filesystem-failure guarantee, and two manually addressed facts do not establish autonomous recall, conversation, or memory correctness at scale.

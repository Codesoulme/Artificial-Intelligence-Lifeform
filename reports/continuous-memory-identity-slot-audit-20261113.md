# 身份槽与事实组合审计

## 目的

区分身份信息是在连续矩阵写入/读取时丢失，还是在连续词元编码到语言输出的桥接器中丢失。所有实验都使用临时矩阵、显式数字地址和隔离候选，不修改正式个体、正式检查点或 DeepSeek 底座。

## 结果

### 连续矩阵身份审计

- 四个姓名的完整词元序列均为两个词元；“小赵”不是单个词元。
- 身份单独写入，以及身份加四种单词元事实写入，共 `20/20` 个案例在两个记忆位置和平均读取上精确恢复。
- 这证明当前连续矩阵和固定编解码器没有丢掉身份序列。
- 旧组合脚本只保留姓名的最后一个词元，确实是有损表示，但不是最新 `0/18` 完整句失败的根因。

### 学习式词元分类头

- 从随机权重训练词元分类头，完整词表随机抽样准确率约 `1.32%`。
- 四个姓名均未能从实际读取向量恢复，姓名测试为 `0/4`。
- 该方案被拒绝，原因是低维随机投影到大词表的直接分类在当前训练量和显存约束下不稳定。

### 身份编解码与事实后缀拆分

- 身份序列使用固定连续编解码器恢复，事实后缀使用独立自回归回答头生成。
- 训练人物：身份、事实、完整句均为 `12/12`。
- 留出人物“小赵”：身份、事实、完整句均为 `4/4`。
- 这轮证明“身份绑定”和“事实后缀生成”可以在受控实验中解耦，优于原先将两者交给同一个语义桥的方案。

## 判定

当前主要问题位于语义桥和文本解码器之间，不是连续矩阵的基本容量，也不是崩溃恢复造成的身份损坏。下一步应设计独立的身份通道、边界/长度元数据和事实通道，并用自然语言写入、未见实体、未见事实、反事实记忆和未知实体拒答进行验证。

本轮仍不能称为开放长期记忆或正常中文聊天，因为地址、写入内容、身份边界和事实模板均由实验程序提供，固定编解码器也尚未接入正式运行路径。

# P113 训练侧前 1 万篇：高频特征参数消融

## 结果

对同一份真实训练侧头部 10,000 条记录，默认 `max_df=0.1` 产生 2,661 条候选、7,339 条隔离；改为 `max_df=1.0` 后产生 10,000 条候选、零隔离。默认组中隔离原因全部为含有被移除的高频特征，并不表示这些记录是重复内容。候选不等于已获准训练。

这是按文件原顺序截取的非随机头部样本，差异不能代表全库，也不能推断全库资源消耗。LSH 可能漏检，包括超过相似度阈值的记录对；字符五元组也无法覆盖语义改写。没有标注真值，因此本试验不测召回率或精确率，零隔离及零达阈值对均不能证明数据没有近重复。

## 资源保护与核验

正式消融运行使用低于普通优先级的真实 Python 子进程；监督器每 0.5 秒检查其当前提交量及系统可用物理内存、可用提交量，阈值分别为 768 MiB、1,280 MiB、1,536 MiB，另设 900 秒墙钟上限。触发时仅终止本试验子进程。保护覆盖结果核验；采样存在间隔，阈值不是绝对硬限制。运行前系统可用物理内存 2,180,739,072 字节、可用提交量 6,425,149,440 字节；采样最低分别为 1,753,919,488 和 5,984,632,832 字节。未触发阈值，退出码为 0。工作集和提交峰值由 Windows 进程计数器记录；上表 CPU 和墙钟只计去重函数，不含后续核验，监督器总墙钟为 47.053 秒。

结果核验确认输入散列一致，所有 10,000 个输入行各属于一个组，代表行是组内最小行，状态与复核原因一致；候选及隔离文件与对应分组逐条一致，四个输出文件散列与摘要一致。这些检查不验证语义正确性。

首次运行因虚拟环境启动器派生了实际 Python 进程，监督器错误地监测了启动器，不能证明子进程提交量阈值受到监控；因此保留其记录但不作为正式消融测量。随后以系统 Python 直接启动并确认监督器的直接子进程就是执行任务的 Python，上表采用这次受监护的复跑。两次运行的记录分别保存在新目录根部和 `guarded/` 下。

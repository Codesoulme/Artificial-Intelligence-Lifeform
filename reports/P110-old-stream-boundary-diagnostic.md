# P110：旧预训练流的文档边界诊断

P109 的故事流已限制注意力在单篇内部，但旧的问答拼接流仍可跨文档：固定种子对 20,000 个 512 目标的旧流窗口抽样，17,578 个包含后续文档的起始标记。窗口比例不是跨文档目标比例，也不表示所有跨边界内容都有害。当前旧流的内容仍经有限审阅，并非新增的高质量连续语料。

从同一 P34 父检查点与原个体出发，保持 P109 的 50:50 旧流／故事计划、均匀短故事采样、种子、计划目标预算和价值观重点回放；将旧流改为单文档窗口，计划训练 200 步，并与 P109 的旧流拼接分支对照。实现使用已有 `DocumentStream`，只预测同一文档内目标，不允许注意力跨越不同文档。文档边界版本也改变长度分布、随机数消耗和实际目标数，且可能仍对文长加权；不能把所有差异独立归因于屏蔽跨文档注意力。

共同使用的旧文本损失来自原有拼接窗口，对旧做法可能有偏；需另外使用相同文档内开发目标比较两组。24 轮对话开发题为已反复使用的诊断集，不是最终验收。运行记录每种来源的实际呈现量，故事不同位置仅涵盖本次运行；原个体和既有检查点应保持不变。数据来源、许可和质量的限制沿用 P107/P109。

## 结果

两组各完成 200 步。按 32 个相同固定开发窗口、16,307 个相同目标加权计算，文档内重置上下文时，P34 父模型、拼接分支、边界分支的 NLL 分别为 3.5120、3.5450、3.5207；保留跨文档上下文但评估同一目标时分别为 3.4879、3.5061、3.5243。另有 77 个文档起始目标只在完整拼接流口径中计入。窗口可能从文档中间开始、可能重复，因而这是同目标开发比较，不是整篇文档或独立验收。

| 200 步指标 | 旧流拼接 | 旧流文档边界 |
| --- | ---: | ---: |
| 实际目标呈现 | 1,752,455 | 1,740,459 |
| 故事呈现 / 本次不同位置 | 875,602 / 857,245 | 869,886 / 850,090 |
| 旧拼接窗口开发 NLL | 3.4266 | 3.4340 |
| 对话开发 NLL | 3.3241 | 3.3279 |
| 故事开发窗口 NLL | 2.6795 | 2.6767 |
| 24 轮开发结束 / 明显循环 | 14 / 5 | 9 / 8 |

两个模型实例对隐藏分支身份并打乱的 48 轮开发回答逐轮评分：两组各 1 轮有用、23 轮无用。已核对匿名标识、场景与轮次；其中两个场景的两条分支由不同实例评分，后续轮次依赖各自先前回答。这是模型盲评，非人工评分或独立验收。边界分支在固定文档内目标上的损失低于拼接分支，但比父模型高；生成仍不合格，不能视为中文聊天突破。仅一个种子，训练顺序和目标数量不同，不能将差异单独归因于注意力边界。

边界分支训练与监测记录约 271 秒、峰值分配显存约 856 MB；早期曾与一项短暂的评测并发，时间不能作为单独吞吐基准。重点文本呈现 309 个目标，原个体张量精确保持，合成探针为 `[7,5,9,3]`。故事不同位置是本次覆盖，不代表祖先未见过。模型检查点、文档内评测和逐轮结果留在 runs；本轮未访问最终测试。

新增 `scripts/eval_p110_document_nll.py`，在相同位置对比三种损失口径，并用四项合成测试核对边界、掩码、加权与抽样。对旧训练流的 4,096 条固定随机记录做了不含正文的机械线索审计，见 P110 数据报告；线索不等于语义分类、隐私确认或整库质量认证。下一步应继续提高真实中文材料质量与对话覆盖，不能因为边界损失改善就认定聊天问题已解决。

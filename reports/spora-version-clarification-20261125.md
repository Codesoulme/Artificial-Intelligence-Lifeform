# 借一次追问读取正确的内部记忆版本

上轮用额外中文样本改善了版次识别，较自由的问句仍常把等待、排除和查阅混淆。本轮把对话动作单独学习，让解码器先决定直接读取、询问版次、暂缓或交还普通对话。借鉴 D4CQ 的做法，把追问是否有用和澄清后的答复一起评测。论文公开摘要可核验，作者给出的 GitHub 地址此次返回 404。 [上轮结果](spora-native-version-families-20261125.md) · [D4CQ](https://aclanthology.org/2026.emnlp-main.22/) · [歧义识别与追问](https://arxiv.org/abs/2605.25284)

## 设计

- 冻结 DeepSeek 的前十二层。用同一组隐藏表示运行上一轮的版次头和新的动作头。动作头以 144 条句子训练 200 步，每种动作在损失中权重相同。训练和留出按人名及表达家族分开。旧头仍处理直接查阅的版次，明确日期及数字版次保留确定性的时间轴约束。
- 候选寻址方式在原有姓名及确切事项边界上加入「记的是」等尾句。使用这个扩展需要显式启用。测试同前缀的事项名、多名人物和相近姓名。
- 追问把已找到的事项、当时的时间轴和可选版次留在会话工作状态。只有紧接的用户回复明确选中一个已提供的版次时才接通内部读取。取消、转题和时间轴变化会关闭该请求。追问措辞由现有有效版次构成，候选只追问一次。
- 读取时从对应的低秩矩阵恢复词元，交给 DeepSeek 的整值读出头。澄清后的生成采用真实的用户、助理、用户三轮消息模板，先前一轮只含追问的选项。评测里的正确值只用于评分。

## 结果

72 条留出问句来自三个新表达家族。直接读取对照和候选使用相同的事项地址、版次头与时间轴；对照对每条都提交直接读取，原有范围检查仍可拦截。另让候选接受标注的首轮动作，测量范围规则及寻址能达到的上限。

| 首轮动作 | 直接读取对照 | 学习动作头 | 给定正确动作 |
| --- | ---: | ---: | ---: |
| 直接查阅并选中正确版次 | 32/36 | 32/36 | 32/36 |
| 应追问时发出追问 | 0/12 | 2/12 | 8/12 |
| 明确暂缓 | 0/12 | 9/12 | 12/12 |
| 交还普通对话 | 12/12 | 8/12 | 12/12 |

对照在 12 条应追问的场景里提前读取 8 次，候选提前读取 6 次。另外，候选对 4 条只请它判断句子是否清楚的话误发追问。对这四个错误状态逐一模拟三个简短版次回复，12 个回复都触发了读取。测试显示一次错误追问会给后续带来错误读取风险。

在真实应追问的两条成功场景中，选择现用、首版或现用前一版的 6 个后续回复，都生成了对应的完整记录并正常结束。以全部 12 条应追问场景为分母，成功为 6/36 个有效后续分支。取消、两项并列和转题均未触发读取。范远清的地点案例里，同一句初问和同一条追问，三种用户澄清分别读到「江畔剧场」「松风书屋」「鹿鸣园」。

启用口语边界后，正确寻址由 24/72 增至 60/72；全部首轮问句都有姓名及事项称呼，部分普通对话原本也不需要定位。四条「事项＋我想找」开头的问句仍未通过，即使给对动作也发不出追问。当前候选留在研究入口。未来需要先区分真实请求和只引用、评价句子的用法，再在真实请求中判断是否需要追问。ClariEdge 的研究用容易误判的近邻负例来区分真正歧义和表面歧义，可借鉴其构造方式。下一轮用同一个问句重写成直接查阅、等待和评价文字三种意图，专门检查错误追问后是否仍能阻断读取。 [ClariEdge 论文](https://arxiv.org/abs/2610.28686)

## 复现

```powershell
$env:OMP_NUM_THREADS = '2'
$env:MKL_NUM_THREADS = '2'
$timeline = 'runs/spora-version-timeline-v2/versions.pt'
$reader = 'runs/spora-version-reply-actions-v1/heads.pt'
$versions = 'runs/spora-native-version-families-v1/heads.pt'
$output = 'runs/spora-version-clarification-v1'
.\.venv\Scripts\python.exe -u -m scripts.audit_spora_version_clarification $timeline $reader $versions $output
.\.venv\Scripts\python.exe -u -m scripts.audit_spora_version_clarification $timeline $reader $versions $output --verify
```

首轮运行约 109 秒，CUDA 张量峰值约 3.47 GiB。独立重载约 106 秒，逐项复现 72 条首轮决策、96 条后续分支和 60 条实际生成的词元。动作头写入 `action.pt`，逐轮记录存于 `result.json` 和 `reload.json`。27 项相关单元测试通过。

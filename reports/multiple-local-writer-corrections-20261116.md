# 多项局部纠错与压缩

## 方法

保留上一轮红茶局部纠错，另从同一个原写入器训练豆浆纠错：程序指定“小赵喜欢喝豆浆”，同时回放 64 个已训练单字，训练 384 步。两个增量分别从原写入器训练，并非依次修改同一持久个体。豆浆门使用一个目标向量、128 个回放负例及红茶锚向量校准；红茶门保留原来的阈值。

组合写入器对每个输入词元计算两个门：恰有一个门开启时使用对应增量；两个门同时开启时回退到原写入器，并记录冲突。回退不保证原写入器答对。当前实现及实验仍由程序指定事实值位置、人物、读取时机和结束词元。

## 组合结果

| 检查 | 仅红茶修正 | 两项修正 |
| --- | ---: | ---: |
| 红茶，2 人物 x 2 问法 | 4/4 | 4/4 |
| 豆浆，2 人物 x 2 问法 | 1/4 | 4/4 |
| 八种饮品，共 32 组合 | 25/32 | 28/32 |
| 留出人物与 64 个留出字，完整生成 | 68/128 | 68/128 |

128 条留出单字输出与仅红茶修正逐词一致。该批 160 条饮品和单字组合没有双门同时开启；人工构造的冲突仅通过单元测试，尚无真实冲突样本。饮品使用两层孢子替换候选，单字对照使用原语言层。新进程加载门参数及来源检查点后，160 条记录逐项复现。

另对 8 人物、4 种表述和 7 种饮品或混合名称做 224 条定位检查；其中红茶及豆浆词元各出现 64 次，各自全部由对应门单独选中，未观察到其他词元误开门或双门冲突。这项检查不生成回答；不同组合共享人物和词元，不是 224 条独立事实，也可能与过去开发或底座预训练重合。

## 低秩存储

两个纠错增量原本由秩 8 适配器训练，实验将保存的完整增量近似分解回秩 8。两项增量的浮点数存储由 18,874,368 字节降至 196,608 字节；包含锚点、阈值及来源绑定的实验工件为 211,472 字节。该大小不包含底座、共享写入器或其他状态。

分解的最大绝对误差分别约 `8.2e-8` 和 `7.9e-8`；重新生成的 160 条记录与完整矩阵逐项一致。独立进程加载低秩工件后也复现了全部 160 条记录。对照程序为了验证来源仍会加载完整候选，并未测得实际运行显存或回复速度节省；更多修正时，匹配和增量计算仍会增长。

## 限制与产物

只测试两种人工词元修正，没有测试连续在线训练、多个事实写入、语义身份、否定、冲突事实或自然停止。尤其第二个候选不是在第一个修正后训练的，不能称为已解决持续学习。分词和名称来自已使用的开发材料；模型仍可能记错其他事实。候选未接入正式个体，状态迁移及实际聊天未验证。

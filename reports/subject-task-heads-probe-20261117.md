# 观察与事实查询的显式双入口试点

依据[自然句回归](fact-head-natural-regression-20261117.md)，新增研究接口 `spora/research_subject_task_heads.py`：调用方必须明确选择观察或事实查询，分别调用对应的定位头；模式不明确、掩码无有效位置或头对象相同则拒绝，不做自动任务识别、隐式回退或分数混合。接口只输出定位分数，不执行身份认证或读写，也没有接入正式聊天入口。

在相同冻结底座上，观察头使用早期交互头，查询头使用多问法候选；模式由实验人工指定。46 条已复核自然单句与 72 条已查看的人工同类查询分别评价，两个头也在对方任务上作控制：

| 检查 | 观察头 | 查询头 |
| --- | ---: | ---: |
| 自然单姓名精确匹配 | 14/24 | 0/24 |
| 自然无明确姓名时选择 | 0/9 | 0/9 |
| 自然多人句选择 | 11/13 | 0/13 |
| 人工同类查询已知精确 | 24/48 | 41/48 |
| 人工同类查询无证据误选 | 24/24 | 12/24 |

自然多人句没有唯一目标标注，不能将选择判为准确或错误；单姓名匹配也不是事实归属。查询组共享两对姓名及模板，已经用作开发检查，不能视为独立自然测试；模式是人工提供，未测试模式判定错误。实验支持不直接将一个头替换另一个，但查询头仍然频繁误选，观察头召回也不足；分流没有解决身份混淆、事实提取或记忆可靠性，不能开放自然写入。

原交互头与候选头摘要均与各自报告核对，底座、检查点、语料包与候选在执行前后未变化；个体未参与。代码 `scripts/deepseek_task_heads_probe_20261117.py`，数字及来源摘要在本机 `runs/deepseek-task-heads-probe-20261117.json`。5 项显式路由和既有数据检查通过。实验脚本依赖本机未跟踪的研究文件，单独检出仓库尚不能完整复现；新增分流模块本身不依赖这些脚本。

下一步应在独立标注的自然对话上评估查询头的错归属、拒答和不同表达，再测试如何识别任务及处理错误模式选择；同时继续检查真正的模型内记忆读取、状态恢复与语言生成，而不是仅优化定位分数。

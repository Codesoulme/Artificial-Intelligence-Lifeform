# 请求边界扩展与选择性寻址

上一轮学习分段器能改善部分普通请求，但对未见的连接词和句尾附加语仍不稳定。本轮增加两种边界改写，分别使用“我打算把……和……记在交接纸上”和“请告诉我……并核实……，随后我会转给别人”。同时保留标注短语、标点切分和原学习切分。参考 CheckList 的成对行为测试和 Description-Driven Task-Oriented Dialog Modeling 的描述迁移，分开记录边界和地址匹配。 [上一轮边界实验](spora-request-spans-20261127.md) · [CheckList](https://arxiv.org/abs/2005.04118) · [Description-Driven Task-Oriented Dialog Modeling](https://arxiv.org/abs/2201.08904)

## 边界泛化

基础分段器使用原有 180 条请求。扩展分段器在同一训练请求上增加两类连接和尾语，留出交接句与追加句。边界指标要求切出的字符串与两条标注请求逐字一致。

| 留出条件 | 基础分段器 | 扩展分段器 |
| --- | ---: | ---: |
| 普通请求 | 0/32 | 0/32 |
| 原换档请求 | 0/12 | 0/12 |
| 新换档请求 | 12/12 | 12/12 |
| 新换档加“再告诉我” | 4/12 | 4/12 |
| 新换档加交接尾语 | 0/12 | 12/12 |
| 新换档加追加尾语 | 0/12 | 4/12 |

普通请求的逐字符精确指标偏严格。模型常保留了两个有效请求，但把开头的“我得把”或句尾的“发给同事”一并纳入跨度。地址选择仍可能正确，因此另列端到端结果。

## 地址匹配与弃权

基础匹配头使用原训练集。增强头增加 16 个同场景近义字段和错场景同名字段。弃权阈值只在独立校准请求上确定。以下使用标注短语，隔离分段因素。

| 条件 | 基础头，默认 | 增强头，默认 | 增强头，校准阈值 |
| --- | ---: | ---: | ---: |
| 普通请求中正确字段 | 33/40 | 30/40 | 30/40 |
| 普通请求中误选字段 | 3 | 6 | 3 |
| 新换档中正确字段 | 10/12 | 8/12 | 6/12 |
| 新换档中误选字段 | 6 | 4 | 2 |
| 新换档无匹配误选 | 6 | 4 | 2 |

增强头的阈值能减少无匹配误读，但同时少读四个新换档中的有效字段。它仍不满足自动读档门槛，未接入本机聊天入口。

用扩展分段器和增强匹配头做完整链路时，普通请求整题正确为 15/32，交接尾语为 5/12，追加尾语为 3/12。给定标注短语时，增强头在普通请求为 22/32，交接尾语为 5/12，追加尾语为 4/12。当前主要误差仍来自字段语义匹配和无匹配弃权，边界模型已经能处理一类未见的尾语，但不能泛化到所有普通句式。
